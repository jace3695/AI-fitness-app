# 실제 SDK 본문 수집과 요청 제어

`508b4ca`에서 통과한 일반 저장·교차 수정·삭제·임시 진행 종료를 반복하기 위한 도구가 아니다. 남은 본문 대조와 요청 시점 제어를 로컬 **전체 Next 앱**에서 수행한다. 인증과 Supabase SDK·서버는 기존 앱 그대로이며, 브라우저 제어 도구에 Network/DevTools API가 없어도 화면의 패널로 조작할 수 있다.

## 실행

기존 작업 폴더의 미커밋 변경을 보존하고 PR의 최신 커밋을 별도 작업 폴더에 준비한다. Node 22.6 이상과 기존 npm 의존성이 필요하다. 저장소 루트에서:

```sh
node --experimental-strip-types scripts/sync-qa/start.mjs 3000
```

실행기는 기존 소스의 **공개** Supabase 주소·publishable key를 개발 환경에 전달하며, 127.0.0.1에만 서버를 연다. 인증·RLS를 우회하지 않는다. 기존 개발용 환경 파일이 있는 폴더에서는 Next 자체가 평소와 같이 환경 파일을 읽는다. QA 도구는 환경 파일·토큰·개인 백업을 수집하지 않는다.

- A: `http://127.0.0.1:3000/?qa-sync=1`
- B: `http://localhost:3000/?qa-sync=1`

서로 다른 origin에서 정상 로그인한다. 로그인 방법 선택·비밀번호 입력은 사용 중인 브라우저 도구의 인증 기능을 따른다. 로그인 완료 전에 화면을 통과로 보고하지 않는다. 테스트 계정 또는 이미 허가된 계정만 사용하고 개인 계정이라면 **기존 17개 키 전체를 먼저 비공개 백업**한다. 다른 활성 세션의 주소와 앱 버전도 기록한다.

`?qa-sync=1`은 해당 탭에서 명시적으로 켜며 같은 origin의 페이지 이동 중에는 유지된다. **development + loopback hostname + opt-in** 모두 충족해야 수집·제어가 켜진다. Vercel 미리보기나 운영 주소, `next build`/`next start`에서는 켜지지 않는다. 기존 통과 미리보기에 이 도구가 자동 적용됐다고 간주하지 않는다.

하단의 **로컬 동기화 검증**을 펼친다. 요청마다 GET/PATCH/POST, 전송·수신·SDK 전달 시각, 응답 상태, JSON 본문, 적용한 제어와 실패 여부를 확인한다. 로그인 요청·다른 테이블·다른 서버는 수집·제어하지 않는다. 헤더는 기록하지 않고 JSON의 user_id와 인증 관련 필드는 마스킹한다. 본문의 개인 운동·설정 값까지 익명화한 것은 아니므로 **JSON 다운로드는 비공개 보관용**이다. 저장소에는 합성 증거나 본문 없는 감사 요약만 추가한다.

## 요청 시점 제어

제어는 해당 탭에서 선택한 메서드의 다음 일치 요청에 적용된다. GET 오류만 해제할 때까지 SDK 재시도에도 적용된다. 30초 폴링이나 포커스 동기화가 먼저 요청을 보낼 수 있으므로, 반드시 실제 적용된 요청 번호와 단계를 패널에서 확인한다.

| 제어 | 실제 동작과 증거 해석 |
| --- | --- |
| 전송 전 보류 | 네트워크에 보내기 전에 대기한다. 요청의 `sentAt`이 없다. 제어 해제 후 원래 요청을 보낸다. |
| 서버 응답 후 전달 보류 | 실제 HTTP 응답을 받은 뒤 본문을 수집하고 SDK에 전달하기 전에 대기한다. PATCH라면 서버 저장이 이미 발생했을 수 있으므로 다른 세션에서 최종 상태를 확인한다. |
| 서버 응답 후 전달 실패 모사 | 실제 응답을 수집하고 SDK에 오류를 반환한다. `response-withheld`에는 서버 응답이 있어도 `deliveredAt`이 없다. TCP 연결을 끊은 검증은 아니다. |
| GET 오류 모사 | 해제할 때까지 GET을 서버에 보내지 않고 합성 503 응답을 SDK에 전달한다. `synthetic:true`로 기록한다. SDK가 자동 재시도하는 요청도 모두 기록한다. 실제 서버의 503 장애 증거는 아니다. |

보류는 120초 안에 **제어 해제**로 풀어야 한다. 잊은 보류는 자동 전송하지 않고 오류로 종료한다. GET 오류는 별도로 해제한다. 대기 중 새로고침·탭 종료를 하지 않는다. 서버에 이미 전송된 쓰기가 취소된다고 가정하면 안 된다.

## 남은 검증 순서

1. **최초 조회 지연**: 첫 조회를 보류할 A를 `http://127.0.0.1:3000/fitness?qa-sync=1&qa-hold=get`로 연다. 로그인 후 첫 대상 GET의 응답 보류 상태를 확인하고, 아직 초기 동기화되지 않은 달력에서 허가된 합성 날짜를 저장한다. 보류를 해제하여 서버 원본과 새 날짜의 병합 및 확인 GET을 대조한다. URL의 `qa-hold=get`는 재로딩 때 다시 적용되므로 다음 실행에서는 제거한다.
2. **엄밀한 조건부 경합**: 두 세션이 초기 동기화된 뒤 A의 GET 응답을 보류한다. B에서 다른 합성 날짜를 저장하고 확인 GET까지 끝낸다. 그 후 A에 준비한 합성 입력을 저장하고 보류를 푼다. 실제 A PATCH의 `updated_at` 조건이 오래되어 응답 본문이 빈 결과인지, 후속 조회·병합·재시도로 양쪽 변경이 유지되는지 확인한다. 원하는 순서가 관찰되지 않으면 이 사례를 통과 처리하지 않는다.
3. **저장 중 추가 입력·이탈**: PATCH 응답을 보류한 상태에서 해당 기록을 다시 수정·저장하고 다른 앱으로 이동한다. 제어 해제 후 추가 수정이 반영되는 후속 PATCH와 확인 GET, 다른 세션 UI를 대조한다.
4. **오류 복구**: 서버 응답 전달 실패 모사 또는 GET 오류를 켜고 실제 앱 오류·로컬 입력 보존을 관찰한다. 제어 해제 후 재시도하고 중복 없이 복구되는지 확인한다. SDK 재시도를 숨기거나 끄지 않는다.
5. **정리**: 각 합성 날짜와 임시 운동을 UI에서 정리하고 자동 동기화를 기다린다. 원본 17개 키 전체를 백업과 비교한 다음 비공개 증거를 내려받고 아래 감사 도구를 실행한다. 모든 제어를 해제하고 처리 중 요청 0건에서 **수집 종료·내용 폐기**, 앱에서 로그아웃, 로컬 서버 종료 순서로 마친다. 개인 앱 저장소 전체 삭제를 정리 수단으로 사용하지 않는다.

```sh
node scripts/sync-qa/audit.mjs scripts/sync-qa/private/session-a.json
```

감사 출력에는 본문 값 없이 요청 번호, CAS 거절, SDK에 응답 미전달, 후속 GET의 일치·불일치·미확보가 나온다. `completeCapture`는 수집 한도·대기·오류에 관한 값이며 전체 앱 통과 판정이 아니다. CLI 종료 코드 0도 입력 형식을 처리했다는 뜻이다. 후속 GET이 해당 쓰기의 확인 호출인지 실행 순서·소스와 함께 판단하고, 원본 보존·UI·정리는 별도 증거로 확인한다. 기본 100건 한도 초과 또는 새로고침으로 끊긴 수집을 완전한 증거로 사용하지 않는다.

## 독립적으로 남은 항목

### 다운로드 파일 접근이 불가능한 내장 브라우저

패널의 **비공개 증거 로컬 파일 보관**은 현재 수집 JSON을 같은 개발 서버의 `scripts/sync-qa/private/capture-*.json`에 새 파일로 저장하고 경로를 표시한다. 표시된 파일을 위 감사 도구에 전달한다. 이 폴더는 Git에서 제외되며 공개 정적 경로가 아니다. 개발 모드·loopback·동일 origin·전용 요청 헤더를 검사하고 서버가 파일명을 생성한다. 운영 모드에서는 404로 거부한다. 실제 인증 토큰·헤더는 기존 수집기와 동일하게 포함하지 않는다. 운동·설정 본문은 개인 데이터이므로 파일을 공개하지 않는다. 저장이 끝난 것을 확인한 뒤 수집을 종료한다.

파일 보관과 감사의 성공은 원본 보존 성공이 아니다. 예를 들어 잘못된 빈 PATCH와 이후 빈 GET도 `confirmation-matches`가 되므로, 반드시 검증 전 전체 원본과 별도로 대조한다.

- 이 개발 환경은 PWA 서비스워커를 등록하지 않는다. 실제 미리보기의 이전/새 서비스워커 업데이트와 작성 중 보류는 같은 preview origin의 두 빌드로 별도 검증한다. 로컬 dev에서 production 환경값을 강제로 바꿔 이 항목을 대신하지 않는다.
- 아이폰 화면 잠금·백그라운드 타이머와 전체 모바일 화면은 최신 고정 미리보기에서 직접 확인한다. loopback 개발 주소는 아이폰에서 열 수 없다.
- 앞의 두 항목은 본문 검증을 기다릴 필요가 없다. 기존 통과를 보존하고 미완료를 독립적으로 기록한다.

자동 확인: `node --experimental-strip-types --test lib/syncQaTrace.test.ts`. 실제 SDK와 loopback HTTP 서버를 사용하지만 인증·RLS·실제 Supabase 서버·브라우저 UI 검증은 아니다. 합성 상태는 메모리에서 폐기하며 실제 계정에 연결하지 않는다.
