# 새 발화 C4 — 기존 공통 답변 화면에 자료 선택 경로 연결

2026-10-27 UTC. **로컬 코드 연결이며 새 문장 음성 생성, 새 발화 품질 검증, 운영 활성화 또는 C4 전체 완료가 아니다.**

## 해소한 공백과 책임

[10월 26일 수용 경로](LOCAL-ARTIFACT-INGESTION-20261026.md)는 `ReplySession`의 선택적 resolver까지만 구현했다. 이번에는 기존 `/assistant`의 `AssistantCharacter`가 그 resolver를 실제 공통 패널에 전달한다. 새 업로드 화면이나 별도 재생·Controller를 만들지 않는다.

```text
기존 서버가 전달하는 한국어/일본어 표본 base64
  → AssistantCharacter: 기존 savedReplyClips 카탈로그 등록
  → ReplyCharacterPanel: resolver 주입 + 세션/화면 수명 관리
  → ReplySession: 확정 답변과 정확히 일치하는 자료 선택, 한 번 load, 파일·문장 해시 검사
  → 기존 LipSyncPlayer → 같은 공통 Controller/렌더러
```

- `createRegisteredReplyClipResolver`는 호출자가 명시적으로 제공한 카탈로그 목록, 파싱한 manifest, loader 함수 참조를 스냅샷으로 보관한다. 사용자 답변을 URL로 만들거나 외부 공급자/전역 가변 저장소를 조회하지 않는다.
- **카탈로그 등록은 바이트 검증이 아니다.** 등록 시 loader를 실행하거나 파일을 해시하지 않는다. 반환된 자료의 바이트는 기존 `ReplySession`이 요청 소유 `AbortSignal`로 한 번 로드하고 검사한다. 실제 디코딩·길이 검사는 기존 player의 별도 책임으로 유지한다.
- `savedReplyClips`는 서버에서 이미 받은 base64 문자열을 각각 캡처한다. 음성이 필요한 정확한 답변만 해당 문자열을 바이트로 디코딩한다. 입력 객체가 나중에 바뀌어도 등록된 loader의 자료를 바꾸지 않는다. 마운트 시 디코딩·fetch·재생은 없다.
- 이미 얻은 원시 바이트를 소유해야 하는 향후 생산자는 기존 `prepareReplyClip`을 사용할 수 있다. 이번에는 별도 저장소/중복 준비 캐시를 추가하지 않았으며, 기존 두 표본 이외의 자료를 등록하지 않는다.
- 패널의 `resolveClip`은 선택적이다. resolver가 없는 기존 검수 화면과 `ReplySession`의 세 인자 호출은 유지한다. 새 문장과 정확히 맞는 자료가 없으면 계속 글 전용이다.

## 교체·취소·중복 응답 처리

- resolver 또는 고정 카탈로그의 실제 교체는 이전 세션을 dispose하고 취소 신호를 전달한다. 아직 유효한 현재 답변은 새 세션으로 전달하되 자동 재생하지 않는다. 이전 resolver가 취소를 무시하고 늦게 완료해도 이전/현재 player에 붙지 않는다.
- 유효한 `performance.responseId`를 답변 식별자로 사용한다. 같은 답변의 props 객체만 복제된 경우 재요청·중복 디코딩·재생 중단이 발생하지 않는다. 같은 ID인데 최종 문장/언어/voice/표정/몸짓/안내 내용이 달라지면 명시적 오류로 거절하고 그 ID를 무효화한다. 다른 내용의 자료를 대신 재생하거나 이전 내용을 새 답변처럼 유지하지 않는다.
- 경로/계정 reset 이벤트, 화면 숨김 또는 취소로 지운 답변은 같은 ID의 새 객체로 전달되거나 자료 소스가 교체되어도 되살리지 않는다. 같은 문장이라도 **새 responseId**인 실제 새 답변은 수용한다.
- 기존 계정별 React key와 상위 답변 소유자 검사는 변경하지 않는다. 컴포넌트 해제 시 미완료 요청을 취소하고 player를 해제한다.
- 직접 누르는 ‘답변 듣기’가 재생을 시작하며, 기존 음성 포커스 이벤트는 다른 재생을 일시정지시키는 조정을 유지한다. 외형·원본 음성·음소 시각·입 전환 로직을 변경하지 않는다.

## 남은 실질적 의존성

1. 선택한 **새 문장의 실제 음성 바이트**와 TTS에 전달된 정확한 문장·언어·voice·파일 길이.
2. **같은 파일에서 측정한** 지원 형식의 음소 타임라인 및 정렬 도구/모델/버전/입력 출처. 시각을 균등 분할하거나 다른 표본을 재라벨링하지 않는다.
3. 해당 자료를 확보하는 합의된 생산자/공급자 경로. 이 코드가 TTS·G2P·강제 정렬·비용/전송/보존 정책을 구현했다는 뜻이 아니다. 현재 일본어 답변 계획은 기존 Gemini Zephyr 선택을 유지한다.
4. 실제 브라우저에서 새 자료의 단일 오디오/Controller 연결, 정지/탐색/오류/새 답변/외형 전환/음성 포커스/경로·계정 전환 확인 및 원본 음향·경계·자연스러움 검토.

새 자료가 확보되기 전에도 공통 UI가 어떤 소스를 소유하고 어떻게 취소·검사하는지는 연결되었다. **자료가 없는 새 발화의 립싱크는 여전히 활성화되지 않는다.**
