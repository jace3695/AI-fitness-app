# 새 발화 C4 — 실제 자료 수용 경로의 로컬 구현

2026-10-26 UTC. **공통 세션의 선택적 자료 수용 경로 구현이며, 새 음성 생성·운영 활성화·C4 전체 완료가 아니다.**

후속: [2026-10-27 기존 공통 답변 화면 연결](COMMON-REPLY-INTEGRATION-20261027.md). 아래의 “UI를 변경하지 않았다”는 10월 26일 작업 당시의 범위이며, 후속 연결 검증과 구분한다.

## 이번에 해소한 구현 공백

기존 `ReplySession`은 생성자에 고정된 저장 표본 목록만 검색했다. 다른 실제 발화의 음성/정렬 자료가 확보되어도 세션이 최종 답변을 기준으로 해당 자료를 비동기로 찾아 받는 경로가 없었다.

- `lib/yeoni/reply-clip-source.ts`의 `prepareReplyClip`은 이미 확보한 음성 바이트와 기존 `LipSyncManifest` 형식의 자료를 수용한다. 파일/정확한 발화문의 SHA-256, 타임라인 구조, 지원 음소·음성 설정을 검사한다. 합성 시계 자료는 거절한다.
- 호출자가 파일을 바꾸더라도 검사와 사용이 달라지지 않도록 해시 계산 전에 바이트를 복사한다. 파싱한 음소 구간은 불변이며 각 `load`는 별도 바이트 사본을 반환한다. 파일당 기존 8MB 제한을 유지한다.
- `ReplySession`의 선택적 네 번째 생성자 인자 `ReplyClipResolver`는 확정된 `ReplyPlan`과 현재 요청의 `AbortSignal`을 받는다. 기존 저장 표본이 정확히 일치하면 resolver를 호출하지 않는다. 미지원/혼합 언어도 resolver를 호출하지 않는다.
- resolver가 반환한 타임라인을 **음성 로드 전에** 파싱·복사하고 문장/언어/voice가 현재 계획과 일치하는지 확인한다. 파일을 받은 뒤 다시 해시를 검사하고 같은 기존 player에 전달한다. 렌더러나 별도 발화 시계는 추가하지 않는다.
- 자료가 없으면 글 전용을 유지한다. 잘못된 자료/실패는 답변 텍스트를 보존한 오류·중립 상태가 되며 다른 표본 음성을 대신 재생하지 않는다. 자동 재시도·자동 재생은 없다.
- 새 요청, reset, dispose 후 완료된 이전 resolver는 취소 신호를 무시했더라도 player를 로드할 수 없다.
- 독립 검토에서 기존 parser가 `String(alignment)`로 배열/객체를 허용하여 `['synthetic-clock-test']`가 합성 자료 거절을 우회할 수 있음을 발견했다. `lip-sync.ts`에서 허용된 **문자열 리터럴만** 수용하도록 고쳤고, 배열·문자열 객체·사용자 정의 문자열 변환 객체를 거절하는 회귀를 추가했다. 원본의 정상 문자열 값은 변경하지 않는다.

`ReplyClip` 타입은 기존 `reply-session.ts`에서도 재수출하여 기존 호출자를 유지한다. **실제 화면의 세 인자 생성자 호출, 공급자, UI, 기능 플래그, DB, 저장 정책은 변경하지 않았다.** 현 UI에서 임의 새 답변은 여전히 글 전용/기존 답변 읽기이며 새 립싱크가 켜지지 않는다.

## 정렬 검증의 한계

SHA-256 일치는 파일과 발화문을 자료에 묶을 뿐이다. 누군가 잘못 만든 음소 시각도 구조가 유효하면 해시 검사만으로 진위를 구분할 수 없다. `automatic-phonemes`/`reviewed-phonemes` 표시는 입력 출처 선언이며 새 청취 승인이나 측정 정확도 인증이 아니다. 실제 디코딩·길이 검사는 기존 `LipSyncPlayer`에서 별도로 수행한다.

이 구현은 TTS, G2P, 강제 정렬, 음량 기반 입 벌리기, 글자별 균등 시간 배분을 만들지 않는다. 측정되지 않은 새 시각이나 원본 음성의 다른 문장 재라벨링도 만들지 않았다.

## C4의 다음 실질적 의존성

1. **선택한 새 발화의 실제 자료:** TTS에 실제 전달한 확정 문장, 지원 언어/정확한 voice, 해당 MP3/WAV 바이트, 실제 재생 길이. 타임라인 parser는 한국어 `ko-KR-Chirp3-HD-Zephyr`, 일본어 `ja-JP-Chirp3-HD-Zephyr` 또는 `gemini-3.8-flash-tts/Zephyr`를 지원한다. 다만 **현재 `buildReplyPlan`의 일본어 선택은 Gemini Zephyr로 고정**되어 있어 일본어 Cloud TTS 자료를 그대로 resolver에 반환하면 voice 불일치로 거절한다. 이 세션에 연결할 자료는 현재 계획의 정확한 voice를 따라야 하며 음성 선택 변경은 이번 범위가 아니다.
2. **같은 파일의 측정 정렬:** 한국어 v1/일본어 Open JTalk v2 타임라인과 원본 음소 시각, 정렬 도구·모델·버전·입력 출처 등의 별도 provenance. 없는 경계는 추정해서 채우지 않는다. 새 파일/문장의 올바른 SHA-256도 필요하다.
3. **자료 획득 서비스:** 합의된 공급자·비용/한도·전송 데이터·취소/재시도·보존 정책에 따라 실제 자료를 얻는 어댑터. 이번 resolver는 그 결과를 받는 계약일 뿐, 서비스나 저장소를 구현하지 않는다. 현재 앱에는 연결하지 않았다.
4. **실제 연결·품질 증거:** 새로운 발화가 기존 단일 오디오/Controller로 재생되는 브라우저 검사, 정지·탐색·오류·새 답변·외형 전환·음성 포커스·경로/계정 변경 확인, 원본 음향과 음소 경계 대조 및 자연스러움 검토. 이 단계가 끝나기 전에 새 발화 립싱크 완료로 올리지 않는다.

작업 중 사용자 PC, 실제 서비스/DB, 비밀정보, 새 TTS·유료 AI·음성 API, commit/push/배포를 사용하지 않았다.
