# 6단계 첫 범위 — 할 일 명령 확인·실행 이력

> 후속 완료: 2026-09-15 같은 탭의 확인 대기·응답 유실 요청 복구를 추가했다. 새로고침 시 명령 재입력을 안내하던 아래 설명은 첫 구현 당시의 기록이다. [최신 복구 기능과 76개 브라우저 검증](assistant-command-recovery.md).

2026-09-15. Zephyr 실제 청구 확인을 기다리는 동안 진행하는 무료 자체 기능이다. 기존 DB와 코드로 동작하며 유료 AI 호출이나 새 요금제가 필요하지 않다.

## 범위와 사용 방법

- **연이 → 연이에게 말하기**, 또는 **Siri 빠른 명령**에 `오늘 할 일에 보고서 작성 추가해줘`를 입력한다.
- 제목·프로젝트·마감일(한국 시간)·우선순위·반복을 보고 **확인하고 저장**을 누른다. 취소하거나 확인 전 새로고침하면 할 일은 바뀌지 않는다. 확인 화면은 15분간 유효하다.
- `할 일 보고서 작성 내일로 변경해줘`로 수정 내용을 먼저 확인한다. 날짜는 확인 화면을 만들 때 확정하며 저장 시 다시 해석하지 않는다.
- **연이 → 실행 이력**에서 변경 전후를 조회한다. **이 변경 되돌리기 → 확인하고 되돌리기**로 추가를 취소하거나 수정 전 값으로 복구한다.
- 할 일은 다른 기기에서 수정·완료·삭제된 상태라면 확인/되돌리기를 거절한다. 실행 응답이 끊긴 경우 같은 확인 화면의 동일 요청 재시도는 중복 생성하지 않는다. 응답을 받지 못한 채 새로고침했다면 **새 명령을 보내기 전에 실행 이력에서 저장 여부를 먼저 확인**한다. 확인 대기 화면의 요청 자체를 새로고침 후 복원하는 범위는 포함하지 않는다.
- 복합 명령에 기록 변경이 포함되면 한 번에 하나씩 요청하도록 안내한다. 앞 명령만 저장하고 뒤 명령에서 실패하는 상황을 피한다.

이번 이력은 **대화·빠른 명령에서 확인한 할 일 추가와 마감일·우선순위·반복 수정** 범위다. 기존 수동 편집, 할 일 완료, 식단·가계부·운동·언어·성장의 명령과 공통 이력 통합은 6단계 후속으로 남는다. ChatGPT 분석방 연결(4단계), 일반 Zephyr 음성 재연결과 실제 iPhone 최종 확인도 완료로 표시하지 않는다.

## 데이터와 복구

- `assistant_task_command_history`에 본인 실행 요청 ID와 변경 전후 원본을 저장한다. RLS·명시적 권한·`security invoker` RPC 2개로 본인 기록만 처리한다. 사용자 키/권한을 사용하며 서비스 키를 브라우저나 Next 환경에 추가하지 않는다.
- 기록과 이력 저장은 같은 DB 트랜잭션이다. 이력 저장 실패 시 기록도 롤백한다. 전체 행 스냅샷 비교로 `updated_at`을 바꾸지 않은 외부 수정도 감지한다.
- 기존 앱 초기화와 같은 사용자 잠금을 사용한다. 연이 초기화는 이력도 삭제하고, 초기화 전 확인 화면의 오래된 요청을 거절한다. 계정 삭제 시 이력도 함께 정리한다.
- 설치 SQL은 기존 개인 기록을 수정하거나 지우지 않는다. 새 이력은 사용자 확인 후에만 생성한다.
- 이력 조회 실패를 빈 목록으로 표시하지 않는다. 새로고침과 이전 이력 더 보기를 제공한다.

## 검증 현황

- 로컬 실제 SQL(PGlite) 11/11 통과: 원자적 저장·응답 유실 재시도·변경/되돌리기·두 세션의 오래된 스냅샷·반복 자식 보호·다른 사용자 차단·만료·초기화·계정 삭제·잘못된 날짜.
- 실제 Auth·PostgREST·Postgres와 Chromium/WebKit의 브라우저 검증을 완료했다. 확인 전 미저장, 취소·새로고침, 실제 커밋 후 응답 유실 재시도, 이력 재조회, 되돌리기, 두 브라우저 충돌, 조회 실패 안내, 390px 화면과 다른 사용자 격리를 검사했다.
- 기능 코드 `1c5c088ab53d4326e3dbc79b8e082973a2f5fb30`의 Preview `dpl_FXFeBCR4dMzWJZJ7MvGnPFkM2Pje`는 READY이고 target은 Preview다. 로그인된 기존 계정에서 실행 이력의 빈 목록·버튼 새로고침·전체 새로고침·연이로 이동을 확인했다. 이 읽기 검증을 호스팅 계정의 할 일 저장/되돌리기 검증으로 표시하지 않는다.
- 호스팅 DB에 `20260915034857_assistant_task_command_history.sql`을 적용했다. 신규 이력 0행, RLS 활성, anon 읽기/실행 차단, 두 RPC의 security invoker와 authenticated 실행 권한을 확인했다. CLI가 만든 초기 로컬 파일명은 실제 적용 버전과 일치하도록 정리했다. SQL 본문은 동일하다.
- 설치 전후 9개 테이블의 행 수와 전체 행 해시가 일치했다: 할 일/대화/프로젝트/기억 각각 0행, 앱 상태 2행, 언어 상태 2행, 지출 36행, AI 사용량 13행, Zephyr 테스트 슬롯 3행. 추가 TTS·AI 제공자 호출은 하지 않았다.
- 보안 검사에서 신규 경고는 없었다. 기존 유출 비밀번호 보호 비활성 경고와 음성용 내부 테이블의 정책 없음 INFO는 그대로이며, 신규 이력 조회 인덱스는 아직 사용 전이라는 INFO만 있었다. RLS 소유자 제한과 명시적 권한을 로컬 SQL에서도 검증했다.
- [CI 실행](https://github.com/jace3695/AI-fitness-app/actions/runs/34926347592)의 단위/DB 345개·VM 25개·lint·타입·독립 빌드는 통과했다. 브라우저는 64/68 통과이며, 신규 테스트 2개가 각 브라우저에서 같은 제목/알림 요소를 둘 찾는 strict-mode 오류로 중단됐다. 할 일 목록과 이력 화면 안으로 확인 범위를 좁혀 재검증한다. 앱 코드나 검증 조건을 완화하지 않았다. 첫 실행의 합성 계정 83개·68개 정리 보고서에서 잔여 행 0, 외부 origin 요청 0을 확인했다.

DB 지침 확인: [명시적 Data API 권한 변경](https://supabase.com/changelog/45329-breaking-change-tables-not-exposed-to-data-and-graphql-api-automatically), [RLS와 소유자 정책](https://supabase.com/docs/guides/database/postgres/row-level-security).

## 최종 결과

수정본 `d1bba48cb8173967e2d22ab72adbb6ba19614dcb`의 [재검증](https://github.com/jace3695/AI-fitness-app/actions/runs/34927247104)은 **성공**했다. 단위/DB 345개·VM 25개·lint·타입·독립 프로덕션 빌드, 브라우저 **68/68** 통과다. 신규 시나리오 3개는 Chromium과 WebKit에서 각각 통과했다. 68개 정리 보고서에서 합성 계정 83개 삭제, 추적 대상 잔여 행 0, 외부 origin 요청 0을 확인했고 임시 DB·볼륨·키도 제거됐다.

동일 수정본의 Preview `dpl_FQUmdX1ShsFrj7YZ7uoXXxoJZnSZ`는 READY다. 동작 코드는 첫 Preview와 동일하며, 첫 실행에서 잘못 지정한 테스트의 확인 대상 2곳과 DB 마이그레이션 파일명/참조를 정리한 수정본이다. 이 결과를 운영 배포나 실제 iPhone 실기기 검증의 완료로 취급하지 않는다. PR 189는 Draft·미병합 상태로 유지한다.

**6단계는 부분 완료**다. 다음 범위는 다른 기록 명령의 확인·공통 이력 연결과 필요한 요청 복구다. 이번 이후 문서만 갱신한 커밋에서는 동작 코드를 바꾸지 않는다.
