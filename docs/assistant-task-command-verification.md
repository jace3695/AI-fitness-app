# 6단계 첫 범위 — 할 일 명령 확인·실행 이력

2026-09-15. Zephyr 실제 청구 확인을 기다리는 동안 진행하는 무료 자체 기능이다. 기존 DB와 코드로 동작하며 유료 AI 호출이나 새 요금제가 필요하지 않다.

## 범위와 사용 방법

- **연이 → 연이에게 말하기**, 또는 **Siri 빠른 명령**에 `오늘 할 일에 보고서 작성 추가해줘`를 입력한다.
- 제목·프로젝트·마감일(한국 시간)·우선순위·반복을 보고 **확인하고 저장**을 누른다. 취소하거나 확인 전 새로고침하면 할 일은 바뀌지 않는다. 확인 화면은 15분간 유효하다.
- `할 일 보고서 작성 내일로 변경해줘`로 수정 내용을 먼저 확인한다. 날짜는 확인 화면을 만들 때 확정하며 저장 시 다시 해석하지 않는다.
- **연이 → 실행 이력**에서 변경 전후를 조회한다. **이 변경 되돌리기 → 확인하고 되돌리기**로 추가를 취소하거나 수정 전 값으로 복구한다.
- 할 일은 다른 기기에서 수정·완료·삭제된 상태라면 확인/되돌리기를 거절한다. 실행 응답이 끊긴 경우 동일한 확인 요청을 재시도해도 중복 생성하지 않는다.
- 복합 명령에 기록 변경이 포함되면 한 번에 하나씩 요청하도록 안내한다. 앞 명령만 저장하고 뒤 명령에서 실패하는 상황을 피한다.

이번 이력은 **대화·빠른 명령에서 확인한 할 일 추가와 마감일·우선순위·반복 수정** 범위다. 기존 수동 편집, 할 일 완료, 식단·가계부·운동·언어·성장의 명령과 공통 이력 통합은 6단계 후속으로 남는다. ChatGPT 분석방 연결(4단계), 일반 Zephyr 음성 재연결과 실제 iPhone 최종 확인도 완료로 표시하지 않는다.

## 데이터와 복구

- `assistant_task_command_history`에 본인 실행 요청 ID와 변경 전후 원본을 저장한다. RLS·명시적 권한·`security invoker` RPC 2개로 본인 기록만 처리한다. 사용자 키/권한을 사용하며 서비스 키를 브라우저나 Next 환경에 추가하지 않는다.
- 기록과 이력 저장은 같은 DB 트랜잭션이다. 이력 저장 실패 시 기록도 롤백한다. 전체 행 스냅샷 비교로 `updated_at`을 바꾸지 않은 외부 수정도 감지한다.
- 기존 앱 초기화와 같은 사용자 잠금을 사용한다. 연이 초기화는 이력도 삭제하고, 초기화 전 확인 화면의 오래된 요청을 거절한다. 계정 삭제 시 이력도 함께 정리한다.
- 설치 SQL은 기존 개인 기록을 수정하거나 지우지 않는다. 새 이력은 사용자 확인 후에만 생성한다.
- 이력 조회 실패를 빈 목록으로 표시하지 않는다. 새로고침과 이전 이력 더 보기를 제공한다.

## 검증 현황

- 로컬 실제 SQL(PGlite) 11/11 통과: 원자적 저장·응답 유실 재시도·변경/되돌리기·두 세션의 오래된 스냅샷·반복 자식 보호·다른 사용자 차단·만료·초기화·계정 삭제·잘못된 날짜.
- 실제 Auth·PostgREST·Postgres와 Chromium/WebKit의 브라우저 검증을 준비했다. 확인 전 미저장, 취소·새로고침, 실제 커밋 후 응답 유실 재시도, 이력 재조회, 되돌리기, 두 브라우저 충돌, 조회 실패 안내, 390px 화면과 다른 사용자 격리를 검사한다.
- CI 결과·Preview 상태·호스팅 DB 설치 여부는 최종 확인 후 이 문서에 기록한다. 준비된 테스트를 통과한 결과로 표시하지 않는다.
