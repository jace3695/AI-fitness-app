# 최종 로컬 후보 검증과 잔여 범위

## 동일 버전 회귀

최종 통합 코드에서 기본 `node scripts/test.mjs` **910/910**, 별도 AI 예산 제어 **26/26**, 합계 **936/936** 통과. 실패·취소·건너뜀 0. 이전 후보의 931과 부분 검사 644를 합산한 수가 아니다. 로그는 `scripts/browser-qa/.generated/final-candidate/unit.log`, `ai-budget.log`이다.

앞선 23파일 제외는 SQL 실행 금지를 보수적으로 적용한 것이었다. 메모리 PGlite, SQL 파일 정적 비교, 합성 API/환경 검사임을 확인하고 이번 명시적 허용 후 전체에 포함했다. 실제 Supabase DB나 거부된 CLI는 사용하지 않았다. 앞서 최종 런타임 코드의 타입·린트·빌드, 이력 UI 9개·캐릭터 UI 15개·운동 음성 UI 3개도 통과했다. 합성 UI를 실제 기기/서비스 통과로 확대하지 않는다.

후보 파일과 각 SHA-256은 `final-candidate-manifest.json`에 고정한다. 후보 해시는 정렬된 파일 경로와 내용 해시 목록의 SHA-256이다. 실제 검증 증거와 파일 사본은 `.generated/final-candidate/`에 보존한다. 커밋/push/게시/배포는 하지 않았다. 원래 미추적 개인/다른 작업 자료는 후보에 포함하지 않는다.

## DB 확인과 승인에 필요한 요약

기존 연결의 프로젝트/테이블 메타데이터만 조회했다. 활성 **Jace App Hub / piqqukiiacncfbztktga**에서 기존 앱 테이블을 확인했고 신규 `public.body_analysis_history`는 없다. 비활성 **AI 가계부 / vzcehalhihtdruetecvb**도 있다. 현재 Preview의 프로젝트 연결과 운영 DB 공유 여부는 아직 미확인이다. 개인 행 내용은 조회하지 않았다.

제안 변경은 신규 분석문 이력 테이블 1개·정렬 인덱스 1개·소유자 SELECT/INSERT/DELETE RLS 3개다. 기존 테이블/기록/권한을 수정하거나 backfill하지 않는다. 사용자가 명시적으로 저장한 분석문만 추가한다. 개별 이력 삭제와 계정 삭제 cascade는 앱에서 복구할 수 없다. 운동/비서 초기화로는 별도 분석문을 삭제하지 않는다는 안내를 추가했다. 원복은 앱 기능을 이전 코드로 돌리고 테이블/데이터를 보존하는 방식이 우선이다. 테이블 삭제는 별도 데이터 보존·삭제 승인이 필요하다. 자세한 범위는 [DB 승인 범위](body-analysis-history/approval-scope.md).
