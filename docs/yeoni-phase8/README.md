# PHASE 8 — 인간형 A안 기본 동작

2026-10-01 10:00 KST 사용자가 인간형 rig-v4 정지 준비본을 확인하고 다음 단계 진행을 요청했다. 승인된 자산을 그대로 사용해 공통 Controller의 깜빡임·숨쉬기·작은 고개 움직임을 연결한다. 기존 고양이·음성 Controller 코드는 변경하지 않는다.

## 동작과 원본 보존

- 원본 투명 머리·몸통을 같은 1024×1536 좌표에서 먼저 재조립한다. 승인된 눈·입 패치를 동일한 feather 경계로 합성한다. 얼굴·의상·머리카락 이미지를 다시 생성하지 않는다.
- 기본 입은 원본 미소다. 깜빡임은 공통 `CharacterFrame.blink`, 숨쉬기는 `breath`, 작은 고개 움직임은 `sway`를 따른다. PHASE 8 화면에 음성·가짜 립싱크를 붙이지 않는다.
- 기본 좌우 고개 회전은 최대 약 0.46도다. 렌더러의 향후 의미 입력을 포함한 상한은 약 1.38도지만 이 단계의 사용자 화면은 기본 동작만 사용한다. 얼굴·승인 눈/입 모든 영역은 같은 강체 변환을 받는다.
- v4의 잠정 목 구간 `[632,816]` 안에서 실제 변형 시작을 y=696으로 좁혔다. 얼굴 전체와 파츠가 변형되지 않게 하고, y=740 머리/몸통 분리선의 양쪽에 같은 연속 변형을 적용한다. y=816 아래 몸통과 하단은 자연스럽게 연결되며 그림 하단은 고정된다.
- 투명 원본을 작은 삼각형으로 겹쳐 그리지 않고, 출력 픽셀마다 원본 좌표를 역산해 알파 가중 보간한다. 투명 외곽의 중복 합성과 격자 틈을 방지한다. 이동·회전에 따른 보간은 있으며 움직이는 프레임 전체의 원본 픽셀 일치를 주장하지 않는다.

## 공통 구조와 정지 정책

`HumanAnimationStage` → `mountCharacterStage` → 같은 `CharacterController` → `createHumanCanvasRenderer`를 사용한다. 별도 발화 시계·음소 매핑·동작 루프가 없다. 기존 기기 표시/움직임 설정을 사용하고 처음에는 정지한다. 수동 정지·숨김·화면 밖·입력 중·모달·동작 줄이기·문서 숨김에서는 공통 루프가 멈춘다. 이미지/Canvas 오류 시 승인된 정지 그림을 표시한다.

기존 최대 30fps 정책을 유지한다. CPU 렌더 표면 폭은 최대 512px로 제한해 높은 DPR에서 픽셀 작업량이 무제한 증가하지 않게 한다. 기본 표정 3개 정도만 캐시하며 프레임마다 React 상태·저장소를 갱신하지 않는다. 일정한 30fps나 물리 iPhone 발열·배터리 성능을 보장한 것은 아니다.

## 재현과 검증 범위

```sh
node scripts/yeoni-human-motion/export.mjs
node scripts/yeoni-human-motion/check-flow.mjs
YEONI_BROWSER=webkit node scripts/yeoni-human-motion/check-flow.mjs
node scripts/yeoni-human-motion/check-visual.mjs
YEONI_BROWSER=webkit node scripts/yeoni-human-motion/check-visual.mjs
```

[독립 동작 미리보기](Yeoni_Human_Motion_Preview.html)는 승인 자산을 내장하며 음성·로그인·서버 연결이 없다. 실행 스크립트가 차단된 ChatGPT 내부 미리보기와 구분하여 실제 브라우저 캡처 영상을 별도로 제시한다.

검증은 두 브라우저의 정지 21개 표정 원본 비교, 움직이는 21개 얼굴 조합, 목 보호 영역 알파, 전체 주기 극단값, 얼굴 확대, 정지 원본 겹침, 어두운 배경, 320/390px·정지 정책·저장 거부·반복 마운트·오류 복귀·외부 요청 및 렌더 비용을 포함한다. 입 7종은 합성 검사용 명시 입력이며 실제 인간형 립싱크 통과를 뜻하지 않는다. 영상은 실제 브라우저 Canvas를 12fps로 캡처한 12초 무음 영상이며 기본 시계를 느리게 재생하지 않는다.

브라우저 결과와 원본 직접 시각 검수를 완료한 후 별도 증거 JSON을 저장한다. PHASE 5 실제 청취는 보류 상태를 유지한다. 이후 PHASE 9에서 기존 MP3/정렬을 연결한다. 운영 병합·배포·새 TTS 생성은 이번 범위에 없다.
