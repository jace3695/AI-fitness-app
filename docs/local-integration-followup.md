## 독립 리뷰와 수정

별도 읽기 전용 검토자가 SQL/API/호출 UI를 검토했다. SQL 실행·서비스 호출은 없었다. 소유자 RLS, API user_id 필터, 예상 계정 검사, 복합 PK, 불변 스냅샷, 개별 삭제 범위에서 교차 계정 접근 결함은 발견하지 못했다. 이는 실제 DB 검증이 아니다.

발견한 P2 두 건을 수정했다.

1. 인증 promise가 끝나지 않아도 15초 후 요청 세대를 무효화하고 버튼 잠금을 해제한다. 늦은 인증 결과는 서버 요청을 시작하지 못한다. 이력 UI 9/9 통과.
2. 운동/비서 초기화 후 별도 저장 분석문이 보존된다는 안내와 개별 삭제 방법을 저장 화면 및 초기화 유지 항목에 명시했다. 실제 삭제 정책/SQL을 변경하지 않았다.

DB 승인에 필요한 구체적인 테이블/정책/영향/복구는 [approval-scope.md](body-analysis-history/approval-scope.md)에 있다. **실제 프로젝트 이름/ref는 로컬에 없으므로 승인 전에 명시해야 한다.** 예시 URL을 대상이라고 추정하지 않았다.

## 운동 안전 보강

`app/data/workoutAdaptiveReview.ts`는 이전에 완료/수행 상태가 없는 기록을 통증 검토에서도 제외했다. 최근 14일 원본 기록에서 기존 통증·악화·저림·동작별 통증 기준을 먼저 검사하도록 수정했다. 수행 횟수에는 미완료 기록을 추가하지 않는다. 미리 본 증가 제안도 새 통증 입력 후 적용할 수 없다. 새로운 의학 기준이나 자동 강도 증가를 추가하지 않았다.

새 회귀는 수정 전 increase/hold 불일치를 재현했고 수정 후 통과했다. 운동 추천/체성분 연결/초기화 단위 37개 통과. 테스트 대역 타입 오류는 올바른 기존 증상 enum과 pending 상태로 수정했다.

## 공통 캐릭터 통합

부모가 지정한 a5bbabd4e93072c1284ab6bd64a67577dc006df0 패치를 정상적으로 읽고, 독립 리뷰와 `git apply --check` 후 패치로만 통합했다. 별도 저장소 전체 이력은 병합하지 않았다. 원래 AssistantClient 수정과 충돌은 없었다.

## 일본어 작업에 전달할 연결 계약

일본어 파일은 수정하지 않았다. `lib/yeoni/speech-participant.ts`의 `createSpeechParticipant(고유ID, 소유한재생중단함수)`를 마운트 때 만들고 해제 때 dispose한다. 새 재생/다시 듣기 직전 claim하고 반환된 lease를 비동기 준비/인증/재생 완료 뒤 확인한다. 중단 함수는 대기 요청의 세대를 폐기하고 해당 재생만 중단해야 한다. 기존 `yeoni-zephyr-play` 이벤트와 ID를 일치시키고 중복 리스너를 만들지 않는다. 음성 생성 호출을 추가하거나 자동 재시도하지 않는다.

경로/계정 변경, 다른 앱 음성 시작, 숨김, 비동기 음성 준비 완료의 교차 순서를 합성 검사한 뒤 실제 기기 재생 확인이 필요하다. 공통 캐릭터는 정확히 일치하는 기존 저장 음성 표본만 립싱크한다. 새로운 답변 음성 생성/일본어의 임의 음소 정렬은 별도 미구현 범위다.
