# 남은 3종: 개발 기준 계약·정지 안내·일반 정보 패널

2026-10-26. **동작 기준 작성은 브라우저나 사용자 PC의 유무와 무관하다.** 이 작업은 이미 있는 설명·도해의 범위를 개발자가 명시하고 실제 모션 모델에 적용하는 계약을 만들었다. 사용자에게 임상 변형을 골라 달라고 하지 않는다.

## 이번에 달라진 기능

- `ExerciseGuidePanel`에서 AB 슬라이더 준비 항목을 열면 기존 `PreparationPoseDemo`가 정지 자세 설명으로 나온다. `sourceExerciseId`가 있으면 이를 우선하고 없으면 `exerciseId`를 사용한다.
- 데드버그에는 **“동작 설명 보기 · 개인 추천 아님”** 접이식 정보 패널을 추가했다. 처음에는 플레이어를 마운트하지 않고, 사용자가 명시적으로 열어야 기존 두 변형을 비교할 수 있다. `DeadBugReviewDemo`의 정보 모드가 범위·속도를 처방값으로 삼지 않음을 표시한다.
- 열면 준비 자세·정지·첫 설명부터 시작하고 직접 재생해야 움직인다. 닫으면 자식을 제거해 재생·변형 선택·진행 위치를 버린다. 다시 열어도 재생하지 않는다. 운동표 선택·추천·기록 저장과 연결하지 않았다. 기존 독립 검토 모드는 그대로 남겼다.
- 폼롤러 회복에도 기본 닫힘 일반 설명 패널을 연결했다. 기존 7장면과 **새로 정의한 외측 대퇴사두근 좌우 2장면**의 정보용 9장면이다. 원 안내의 “바깥 허벅지”가 뜻한 조직을 확인한 것이 아니다. 기존 `rollerRecoveryStages`의 7+2 보류 구성과 새 정보용 구성을 구분한다. 출처·접촉/지지 기준·검사는 `ROLLER-INFORMATIONAL-REVIEW-20261026.md`에 기록했다.
- AB는 무릎·손잡이·바퀴 접촉을 보여 주는 **밀지 않는 준비 도해**다. 재생·롤아웃·새 유지 시간·횟수·주차 처방은 추가하지 않았다.
- `ExerciseMotionDemo`의 세 항목 `null`은 그대로다. **기본 디스패처 시연 27종 + AB 정지 준비 안내 1종 + 선택 열기 일반 설명 2종(데드버그·폼롤러 회복)**을 구분한다. 정보용 장면 구현을 원 루틴의 개인 적합성·의료 검수·실사용 검증 완료로 세지 않는다.
- 기존 운동 설명·중단 기준·추천·필터·저장/DB는 변경하지 않았다. 기존 안내에 들어 있는 주차·거리·시간 문구를 새로 임상 검증했다는 뜻도 아니다.
- 이 변경은 로컬 구현이며 실제 브라우저·기기·운영 배포 검증은 하지 않았다.

## 기준의 근거와 권한

1. `app/data/exerciseGuides.ts`: 현재 카탈로그의 동작 의미와 순서. 사용자 개인에게 유효한 의학적 처방의 근거로 취급하지 않는다.
2. `BATCH12.md`: AB의 밀지 않는 정지 준비 범위. `BATCH22.md`: 이미 정의된 롤러 7장면의 대상/지지/접촉 구조. `BATCH23.md`: 데드버그 교대형·팔만형 두 검토 초안의 범위.
3. `NEXT-SCOPE-REVIEW.md`, `INTEGRATION-27.md`: 과거 보류 판단과 통합 상태. 개발자가 작성한 이전 미연결 정책이지, 일반 정보용 도해 제작 자체를 금지한 별도의 사용자 지시라고 해석하지 않는다.
4. 2026-10-26 기준 계약·AB/데드버그 연결 시점에는 이전 문서의 NASM·ACE 등 출처를 새로 조회하지 않았다. 이후 폼롤러 일반 정의 작성에서 공개 물리치료·정형외과 자료를 확인했다. 해당 4개 출처와 채택/제외 내용은 `ROLLER-INFORMATIONAL-REVIEW-20261026.md`를 참조한다. 어느 출처도 임상 승인·개인 안전성 근거로 격상하지 않았다.

**일반 동작 설명과 개인 운동 추천은 다르다.** 일반 설명의 프레임·지지점·순서·표시를 개발할 수 있다. 특정 개인에게 적합한 변형·동작 범위·진행 단계는 이 계약으로 결정하지 않는다. 특히 작은 그림 좌표나 재생 속도를 안전한 각도·거리·시간으로 변환하지 않는다.

### 이미 정의된 롤러 지지 구조

| 대상 | 바닥/몸 지지 | 그림에서의 접촉 대상 |
|---|---|---|
| 종아리 좌우 | 양손 + 반대 발 | 선택한 종아리의 초록 표시 안; 무릎/발목으로 이동하지 않음 |
| 앞 허벅지 좌우 | 양쪽 전완 + 반대 발 | 선택한 앞 허벅지의 초록 표시 안; 무릎/골반 끝으로 이동하지 않음 |
| 엉덩이 좌우 | 양손 + 반대 발; 작업 쪽 발목–반대 무릎 접촉 | 선택한 엉덩이 초록 표시 안 |
| 등 위쪽 | 양발 + 롤러; 양손은 머리와 함께 이동 | 등 위쪽 초록 표시 안; 목/허리로 이동하지 않음 |

`rollerDrawingTarget`의 숫자는 기존 `RollerFigure`의 초록 표시 경계 좌표다. 경계 밖으로 접촉점이 벗어나는 그림 결함을 검출하려는 값이지 실제 신체의 안전 여유 거리나 마사지 범위가 아니다. `epsilon`도 부동소수점 오차 허용값일 뿐이다. AB의 선 두께 보정 역시 SVG 접촉 계산이다.

## 단순히 현재 출력에 맞춘 성공 테스트가 아닌 검출 확인

실제 모션 모델의 401개 데드버그 프레임(각 변형)과 롤러 201개 프레임(각 7장면)을 검사한다. 이 표본 검사만으로 모든 시각적 자연스러움이나 연속성·해부학적 정확성이 증명되지는 않는다.

별도 변이 입력으로 다음 오류가 **실제로 거부되는지** 확인한다.

- 데드버그: 같은 쪽 팔/다리 움직임, 움직임 없이 고정된 팔, 골반 이동, 팔 길이 늘어남, 팔만형의 다리 이동, 좌우 사이 중립 미복귀.
- 롤러: 바닥에서 뜸, 신체와 접촉 분리, 손/발 지지점 미끄러짐, 잘못된 지지 다리, 좌우 바뀜, 접촉점이 표시 대상에서 이탈, 회전과 이동 불일치, 정지 그림을 모션으로 처리, 전완/발목–무릎/손–머리 접촉 이탈.
- 회복 구성: 보류 장면 재생 허용, 보류 장면 삭제, 임의로 IT밴드로 이름 변경, 기존 움직임 장면을 정지로 변경.
- AB: 앞으로 민 바퀴/손, 뜬 바퀴, 뜬 무릎, 몸통 정렬 변경, 롤아웃 ID 별칭.

이번 검사에서 기존 모델의 새 기하 결함은 발견되지 않았다. 이를 실제 자세 전문가 검수나 브라우저 화면 검수 통과로 보고하지 않는다.

## 앱 구성 회귀

`tests/motion-validation-paths.test.ts`의 기존 dirty 작업을 보존하면서 AB/데드버그 연결 기대값을 갱신했다. 이후 회복 정보 패널의 정확한 분기는 별도 `tests/roller-informational-review.test.ts`에서 추가 검사했다.

- 직접 움직임 진입점은 27 활성/3 미연결 유지.
- 실제 `ExerciseGuidePanel`의 30개 ID + 미지원 ID, `sourceExerciseId` 유무를 합성. AB만 별도 정지 SVG 1개이고 모션 슬라이더는 없음. 데드버그와 폼롤러 회복의 초기 마크업에는 닫힌 정보 패널만 있으며 그림/모션 플레이어는 없다. 해당 설명을 명시적으로 열면 각각의 정보용 플레이어를 마운트한다.
- `sourceExerciseId`와 `exerciseId`가 서로 다른 운동일 때도 원본 ID 우선; 일반 ID 경로도 유지.
- 기존 경고/움직임 설명/중단 안내 보존. guide가 사라지면 표시 없음. 독립 정지 도해의 캡처 루트 제거와 미지원 ID 빈 렌더 확인.
- 이는 서버 초기 마크업/구성 검사다. 실제 브라우저 화면 전환·효과·레이아웃·언마운트 동작을 실행한 검사가 아니다.

### 데드버그 이벤트·효과의 비브라우저 검사

`tests/dead-bug-informational-review.test.ts`는 실제 wrapper·`DeadBugReviewDemo`·`StagedMotionDemo` 함수와 effect cleanup을 실행한다. React 훅 상태와 effect 스케줄링, matchMedia/visibilitychange, RAF만 메모리 하네스로 대체한다. 네트워크/저장 호출은 예외로 거부한다.

- 실제 wrapper의 toggle 핸들러로 열고 닫아 조건부 자식 추가/제거를 검사한다. 닫힌 최초 상태에는 플레이어 effect·RAF가 없다.
- 열 때 정지/0/첫 변형, 수동 재생의 진행, 닫을 때 예약 RAF 및 리스너 정리, 다시 열 때 변형·위치 초기화를 검사한다.
- 변형 변경, reduced-motion 설정/해제, 백그라운드 처리, 제거 뒤에 자동 재생이 생기지 않는지 검사한다.
- 관계없는 하위 toggle 이벤트가 외부 패널을 열지 않는지 검사한다.

실제 DOM/hydration/브라우저의 native toggle 이벤트 순서·포커스·레이아웃은 시뮬레이션하지 않는다. 호스트 ref도 실제 DOM이 아니므로 상위 details 감지 동작은 이 하네스의 검증 범위가 아니다. 해당 항목은 실제 브라우저 검사에 남긴다.
