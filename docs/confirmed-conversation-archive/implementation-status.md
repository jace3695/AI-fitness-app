## 검사와 증거

신규 API/스키마/메모리 SQL 6개 및 신규 실제 컴포넌트 브라우저 10개 통과. 첫 API 합성 검사에서 VM 객체 원형을 deepEqual로 비교한 검사기 문제 1개가 있었고 필드 값 검사로 고쳤다. SQL RLS 검사 자체는 처음부터 통과했다. 브라우저 첫 번들 시 합성 인증 함수의 닫는 괄호가 하나 빠져 실행 전에 실패했고 수정 후 10개 흐름이 통과했다. 권한 거부 우회나 외부 서비스 접근은 없었다.

실제 Next 브라우저는 37개 검사 통과, 런타임/콘솔 오류 0, 외부 origin 요청 0. 양 외형에서 일본어 보관·새로고침·재조회, 비서 체성분 질문/답변의 명시적 보관을 추가했다. 인증·REST·보관 API는 격리 합성 응답이며 실제 Auth/DB 저장의 증거가 아니다. 실제 마이크는 차단했다. 작은 화면은 뷰포트 검사이며 물리 키보드 검사와 다르다.

기존 대화 브라우저는 닫힌 미리보기 안의 동일 문장까지 중복 매칭해 처음 실패했다. 미리보기를 열 때만 내용을 렌더링하도록 보완한 뒤 18개 흐름을 통과했다. 초기 실패 로그는 별도 보존한다.

최종 전체 회귀·타입·린트·기존 이력/대화/일본어 브라우저·프로덕션 빌드 결과는 `scripts/browser-qa/.generated/archive-integration/verification.json`과 새 후보 manifest에 기록한다. 이전 후보의 통과 수를 합산하지 않는다. 신규 증거는 `confirmed-archive/`, `next-archive-integration/`에 보존한다.

최종 동일 코드 결과: 전체 단위/정적/합성 SQL **926/926**, 별도 AI 예산 **26/26**, 합계 **952/952** 통과(실패·취소·건너뜀 0). 전체 타입, 변경 범위 ESLint(경고 0), 프로덕션 빌드 통과. 실제 컴포넌트 브라우저는 신규 보관 **10**, 기존 분석 이력 **9**, 기존 체성분 대화 **18**, 일본어 연습 **13**, 기존 회화 **16**개가 각각 통과했고, 실제 Next 레이아웃/페이지의 합성 통합 **37**개도 통과했다. 빌드까지 외부 연결 차단/합성 설정을 사용했다. 실제 DB·제공자·마이크·기기 검증은 미실행이다.
