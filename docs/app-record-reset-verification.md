# 앱별 기록 초기화 및 일본어 실사용 검증

작업일: 2026-09-06. PR #186의 일본어 개선에 사용자 추가 요청을 반영했다.

최신 상태(2026-09-07): 아래 이력에서 보류됐던 음성 성공 재생과 320·390px 학습·설정·초기화 확인/취소 검증을 완료했다. 후속 결과와 검증 범위는 [공통 TOP 및 후속 실사용 검증](common-scroll-top-verification.md)의 마지막 절을 참고한다.

## 삭제 범위

| 앱 | 삭제 | 유지 |
|---|---|---|
| 운동 | 운동·세트·철봉 진도, 체중·체성분, 컨디션·메모, AI 분석·선택 이력 | 운동표·설정·체중 목표·알림, 식단 |
| 식단 | 식사·단백질·물·공복, 외식·증상 기록 | 식단 설정·시작일, 운동·체중 |
| 일본어 | 가나·수업 진도·점수·초안, 오답·복습·달력, 저장 단어·문장 | 교재와 학습·음성·캐릭터 설정 |
| 자기계발 | 루틴 실행·타자·손글씨 연습 기록, 주간 코칭 | 루틴·목표, 자료함 파일·작품, 운동·일본어 원본 |
| AI 연이 | 대화·기억·할 일·대기·프로젝트·앱 등록 일정 | Google 원본 일정·연결, 알림, 타 앱, AI 요금·한도 |
| 가계부 | 전체 기간 지출·수입·저축 | 예산·반복지출·통화·보안 설정 |

통합 달력에는 별도 원본 기록이 없어 각 앱 설정으로 연결한다. 통합 설정에서도 모든 앱의 기록 관리에 접근할 수 있다. 로그인·비밀번호·PIN·생체인증은 초기화 대상에 포함하지 않는다.

## 구현과 보호

- 앱 이름·대상 계정·삭제 및 유지 범위 표시, 확인 체크 및 `초기화` 입력 후 최종 삭제 버튼 활성화.
- 기존 가계부는 비밀번호 재확인 및 최종 확인을 유지한다. 화면에 로드된 배열을 반복 삭제하던 동작을 전체 기간의 DB 트랜잭션으로 교체했다.
- `reset_my_app_records`는 `auth.uid()`에서 대상을 결정하고 SECURITY INVOKER로 RLS를 적용한다. 사용자 ID를 입력받지 않는다. 공개·비로그인 실행을 금지한다.
- 각 앱의 테이블과 JSON 키를 명시한다. 다른 앱·설정 키를 전체 접두사 삭제하지 않는다. 일부 삭제 실패 시 전체 DB 작업을 롤백한다.
- 요청 UUID를 재사용해 응답 유실 후 같은 작업을 재확인할 때 다시 삭제하지 않는다. 계정 전환 전후 사용자 ID를 검증한다.
- 초기화 세대 정보를 동기화 병합에 반영해 이전 기기 기록이 자동 복원되지 않게 한다. 자기계발의 이전 완료 백업 자동 이전도 중단한다. 같은 기기의 다른 탭은 새로고침한다.
- 사용자가 직접 선택하는 백업 복원은 현재 초기화 세대를 유지한 새 복원 작업으로 처리한다.
- 다른 기기·탭에서 진행 중인 입력과 분석은 끝낸 뒤 초기화하도록 안내한다. 브라우저를 오래 열어 둔 이전 배포의 동작까지 보장하는 것은 아니다.

## 확인한 실사용 및 수정

- 프리뷰 실제 로그인 후 새 일본어 홈·캐릭터 확인.
- 5분/처음 배워요 선택 → あいうえお → 오답 안내 → 재선택 → 묶음 저장 성공.
- 새로고침 후 다음 가나 묶음(か 행)으로 이어지는 것을 확인.
- 인사말 수업의 표현 → 문장 → 대화 → 한 문제씩 화면 진입 및 오답 안내 확인.
- 5분 수업 완료: 첫 선택 1/3, 재도전 포함 2/3. 오답 선택 상태도 새로고침 후 복원됐다. 남은 오답 1개를 복습에서 힌트 → 정답 → 저장했고, 새로고침 후 오늘 복습 0개로 유지됐다.
- 새 프리뷰 주소에서 다시 로그인하자 클라우드의 1/60 수업 진도와 5분 설정을 불러왔다. 10분·20분 분량 안내 변경과 20분 두 번째 수업 시작·중간 저장도 확인했다.
- 운동·식단·일본어·자기계발·AI 연이의 기록 초기화 화면에서 대상 계정, 삭제/유지 범위, 초기 버튼 비활성, 취소 후 복귀를 확인했다. 일본어에서는 체크만으로 비활성 유지, `초기화` 입력 후 활성화, 취소까지 실제 조작했다.
- 가계부 설정에서 전체 기간 삭제 안내, 비밀번호 재확인 양식 열기 및 취소를 확인했다. 비밀번호 입력이나 최종 삭제는 실행하지 않았다.
- 첫 글자 듣기 실패를 실제로 발견했다. Vercel 로그에서 `POST /api/language/tts 401` 확인. 인증 토큰을 보내는 기존 `authenticatedFetch`로 수정하고 인증 전달 회귀 테스트를 추가했다.
- 수정 프리뷰에서는 401 대신 500이 발생했다. 서버가 오류 단계를 기록하지 않아 원인을 단정할 수 없었다. 설정 누락·외부 음성 실패·내부 단계 오류를 구분하는 로그 및 안전한 사용자 안내를 추가했다. 성공 재생은 아직 확인하지 못했다.
- 후속 프리뷰 `dbab9ca`에서 원인을 확인했다. 실제 듣기 요청은 HTTP 503, Vercel 로그는 `[japanese-tts] configuration_missing`을 반환했다. `GOOGLE_TTS_API_KEY`가 프리뷰 서버에 없다. 화면도 "음성 서비스 설정이 아직 준비되지 않았어요"로 정확하게 표시한다. 키 값이나 환경변수 변경 기능은 이 작업 연결에 제공되어 있지 않다.
- 고정 브랜치 프리뷰에서도 완료 수업 1개, 20분 수업의 두 번째 표현까지 클라우드에서 복원됐다. 통합 달력 → 설정 → 앱별 기록 관리 이동을 확인했다.
- 일본어 초기화의 최종 버튼은 페이지 하단까지 스크롤하면 하단 공통 메뉴 위에 정상 표시된다. 비활성 색상·확인 입력·취소 버튼을 실제 스크린샷으로 검수했다.

## 자동 검증·DB 확인

- 145개 테스트·ESLint 통과. 운영 빌드에서 타입 검사와 45개 정적 페이지 생성 성공.
- 신규 검증은 앱별 삭제 범위 분리, 초기화 전후 두 기기 병합, 초안 부활 방지, 명시적 백업 복원, 로그인 저장값 보존 및 음성 인증 전달을 포함한다.
- 원격 Supabase 마이그레이션 `20260906141943_add_app_record_resets` 설치 성공. 함수 설치 자체로 기존 기록을 삭제하지 않았다.
- 함수 권한 조회 결과 SECURITY INVOKER, 빈 search_path, anon 실행 금지, authenticated 실행 허용을 확인했다.
- 보안 Advisor에서 이번 변경에 대한 새 RLS 경고는 없었다. 기존 [유출 비밀번호 보호 미활성 경고](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection)는 별도 계정 보안 설정이며 이번 범위에서 변경하지 않았다.
- CLI 설치 경로의 네트워크 승인 취소 이후 다시 설치하지 않았다. 연결된 Supabase의 마이그레이션 기능으로 설치했고, 서버가 반환한 버전 번호로 SQL 파일을 기록했다.

## 아직 완료하지 않은 실제 검증

수정된 프리뷰의 음성 성공과 작은 화면·확대 검증이 남아 있다. 현재 브라우저의 1363px 화면에서는 가로 넘침이 없었다. 브라우저 확대 단축키로 뷰포트가 변경되지 않아 작은 화면 검증으로 세지 않았다. 자동 테스트와 DB 함수 설치를 실제 삭제 검증으로 대체하지 않는다.

일본어 실제 삭제는 아래와 같이 사용자 확인 후 완료했다. 다른 앱의 전체 기록 삭제는 실행하지 않았다. 핵심 실사용 검증이 통과하기 전에는 PR을 병합하거나 운영 프런트엔드를 배포하지 않는다.

## 일본어 실제 초기화 검증 완료 — 2026-09-07 KST

사용자가 계정과 일본어 전체 기록 삭제 범위를 명시해 승인한 뒤, 프리뷰 `d9066bb`의 설정 화면에서 실행했다. 관리자 SQL로 삭제하거나 사용자 인증을 대신 만들지 않았다. SQL은 삭제 전후 비교와 재조회에만 사용했다.

- 초기화 전: 완료 수업 1/60, 진행 중인 20분 수업, 기존 과정 복습 기록을 확인했다. 두 번째 탭에도 같은 진도가 표시됐다.
- 대상 계정 확인 → 초기화 화면 열기 → 확인 체크 → `초기화` 입력 → 활성화된 최종 삭제 버튼을 실제 클릭했다. 완료 안내와 자동 새로고침을 확인했다.
- 열린 두 번째 탭은 별도 조작 없이 첫 글자 학습·완료 수업 0/60으로 갱신됐다. 이후 두 탭에서 새로고침해도 초기 상태를 유지했다.
- 복습 화면: 저장 단어·문장, 가나·문법 복습, 과정 복습 및 전체 보관 항목 모두 0개.
- 학습 진도 화면: 연속·총 학습일 0일, 수업 시도 0회, 평균 점수 0점, 세 과정 모두 0/20. 진행 중 수업도 사라졌다.
- 설정 화면: 기존 20분 설정을 유지했다. 클라우드에 저장된 일본어 설정 전체의 비교 해시도 삭제 전후 동일했다.
- 별도 클라우드 재조회: 기존 수업 진도·초안·복습 키는 제거됐으며 초기화 시각 표시는 남았다. 홈이 다시 생성하는 오늘의 기본 기록은 완료 항목이 빈 배열이고 완료 수 0인 정상 초기값이었다.
- 다른 앱 데이터와 일본어 설정을 포함한 14개 비교 범위의 행 수·내용 해시가 모두 동일했다. 가계부 전체 기간 내역, 운동·식단 상태, 자기계발 루틴·기록·자료, 비서 데이터의 변경은 없었다.
- 앱 출처로 필터한 브라우저 오류 로그에서 새 오류는 없었다. 검증 후 새 학습 기록을 만들지 않아 초기 상태를 유지했다.

이 결과는 일본어 실제 삭제와 같은 브라우저의 두 탭 동기화를 검증한 것이다. 다른 앱의 실제 삭제나 별도 물리 기기 검증까지 완료했다는 뜻은 아니다. 공개 검증 문서에는 계정 주소·사용자 ID·개인 기록 본문을 포함하지 않는다.
