## Editor, authority and immutable intent rules

Each event handler is bound to the rendered registered context, owner epoch, marker, local participant generation and selected session. A cached callback from another owner, owner ABA, retired context or previously selected session cannot acquire the new context. Reads and each asynchronous acknowledgment recheck current registered authority. Same-owner pause keeps input mounted in memory but exposes no private text and permits no writes. Owner/reset events retire callbacks and clear private UI state immediately. Participant-only generation replacement clears only the conversation editor; no unrelated editor is remounted here.

Idle typing captures exact raw input, immutable draft ID/revision/timestamp, original/inserted-and-edited facts, exposure facts and registered source before awaiting the facade. Writes are serialized. Exact whitespace and Unicode are preserved; over-limit input stays intact with a visible error, without truncation or eviction.

Newer input typed while revision N awaits acknowledgment remains in memory as visibly unsaved N+1. N's acknowledgment advances only its exact saved predecessor and cannot mark N+1 saved. N+1 requires a fresh explicit Save. That save verifies the same lane still equals its expected predecessor; a competing writer's changed lane is not overwritten. A known conflict can be resolved by explicitly confirming that the unsaved in-memory input may be discarded and the current saved draft restored. An uncertain original operation cannot be discarded or silently reissued through this control.

An append pins the exact submitted draft lane. New typing uses a new in-memory lane rather than replacing an already-occupied second lane. At most two lanes may persist. If both are occupied, additional input remains visibly unsaved until the user explicitly selects an available recovery action; neither lane is silently replaced. Repeated send/end clicks cannot create multiple original operations. Enter during composition, key code 229 and repeated keydown are suppressed; actual browser IME remains unverified.

Example, reading, meaning and hint exposure is recorded only after the corresponding visible page elements commit. Display facts are sticky across edits and draft selection, including facts retained in the same session. A response's post-answer hint affects later input only after it is actually rendered. Inserted-example and inserted-then-edited remain separate from typed input. These are factual provenance fields, never proof of independent production or language quality.

## Save, navigation and uncertainty

The UI distinguishes unsaved input, a write awaiting acknowledgment, a persisted pending append/close, uncertain result, and current locally saved state. No raw host error, malformed record or untrusted exception is displayed.

App-owned history, scenario, new-session, draft-selection and close actions preserve the current input first and refuse to navigate on failed/uncertain preservation. They recheck newer typing after every await. Send/end/navigation bind the exact rendered session head, ordered turn references, frozen source, closed/pending boundary and editor payload. The first read and every post-await fresh read must still match before command capture or selection; a competing same-lane save cannot substitute unseen text, and an other-lane append cannot silently move the intended head. A returned save acknowledgment is reread against its exact saved lane. After session creation, the previous visible editor/head and the new session are checked again against fresh original-context bytes before changing selection. Unknown creation recovery acknowledges the proven new session without navigating away from an existing editor. Creation/deletion/close transitions fence editing; save and append still preserve newer typing. Browser Back, reload, pagehide, tab kill and crash cannot reliably await asynchronous storage. A beforeunload warning and explicit UI caveat identify that unconfirmed last input may be lost; there is no raw-storage unload fallback or promised unload flush.

Recovery reads the exact original operation or edit identity under a current registered snapshot. It never rebinds or resends an old uncertain intent. A restarted pending append/close offers explicit cancellation under a new current-source command. Append cancellation retains its pinned input as unsent; close cancellation creates no draft and preserves existing drafts. Applied terminal results win races. Missing operations are unresolved, not proof of no commit.

A missing selected session/partition reports unavailable history and does not become an empty successful session or trigger automatic enrollment. An unknown deletion has one narrow recovery exception: its original registered edit may inspect the same owner/generation's exact tombstone even though the selected session is gone. Tombstone proof is required before acknowledging deletion.

End stores a frozen closed boundary and preserves any unsent drafts separately. Unsent drafts do not increase the sent-turn count. Closed recaps use the exact saved source, emitted responses, comparison policy, summary policy and complete closed coverage. Unsupported/unknown coverage is unavailable. “Well-used expressions” and “correctable expressions” remain unassessed, without scores, zero-error or naturalness claims. Last authenticated observation is explicitly the client receipt time of an authenticated server response, not a signed server timestamp or assurance that no later reset occurred.

## Local deletion and privacy

Deletion requires a separate explicit irreversible-local-only confirmation tied to the exact displayed session source. A changed source invalidates the confirmation. Confirmation does not silently capture a newer session. It removes only that session and creates its generation tombstone; it is not a real-user-data tool validation operation. All development verification uses synthetic owners and synthetic records only.

Conversation input, transcripts, drafts, pending payloads, receipts and local journal content remain outside cloud/provider payloads, notifications, URLs, logs and backup exports. Native local StorageEvents may contain old/new values inside the origin; this hook neither reads nor copies them. Existing record notifications can wake the existing language coordinator, whose ordinary metadata checks are unchanged; the claim is conversation-content isolation, not zero network activity by the entire app.

The reviewed ceilings remain 262,144 UTF-16 code units per owner envelope, 25 sessions, 500 total turns, 200 per session, 8,000 code units per input and two persistent draft lanes. These are not reserved origin quota or browser durability guarantees. No eviction, receipt pruning, silent normalization, new namespace or fallback storage is added.
