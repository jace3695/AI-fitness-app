# OA 긴 건강보고서 누락 항목 보완 — 로컬 검증

이 변경은 로컬 개발 상태다. 커밋, push, Preview/운영 배포, 실제 건강기록 저장은 하지 않았다. 기존 기록을 자동 변환하지 않는다.

## 원본 항목 인벤토리

허용된 원본 두 장을 각각 네 영역으로 나누어 확대 대조했다. 개인 수치·날짜·시간·이메일·사진과 기대값은 저장소 밖 `private-ocr`에만 둔다. 코드 인벤토리는 `app/lib/oaReportInventory.ts`이며, 개인 데이터 없이 다음 30개 항목을 정의한다.

| 구분 | 원문 항목 | 개수 |
| --- | --- | ---: |
| 대표 숫자 | 체중, 점수 | 2 |
| 일반 숫자 | 체지방률, 근육률, BMI, 골량, 단백질 비율, 기초대사, 내장 지방 지수, 신체연령, 무지방 체중, 피하지방률, 수분, 피하지방량, 근육량, 지방량, 표준 체중 | 15 |
| 부위 숫자 | 왼손/오른손 지방량, 체지방량, 왼쪽/오른쪽 다리 지방량, 왼손/오른손 근육량, 신체 근육량, 왼쪽/오른쪽 다리 근육량 | 10 |
| 문자 결과 | 체형 | 1 |
| 측정 시점 | 날짜, 시간 | 2 |

숫자 27개에 체형·날짜·시간을 더한 30개다. 연령의 단위 문자열은 숫자 항목에 딸린 정보이며 별도 측정값으로 세지 않는다. 상태 배지 13개, 체중/체형 그래프의 기준값·범례, 권장 설명 문장은 개인 측정값과 구분하고 이번 저장 범위에서 제외한다.

## 저장 의미와 호환성

- `standardWeight`: 보고서의 표준 체중. 사용자 목표체중을 수정하지 않는다.
- `reportedBodyAge` + `reportedBodyAgeUnit`: 원문 숫자와 `연령 단위` 표기. 기존 `bodyAge`(세) 기록을 덮어쓰거나 나이 구간으로 추정하지 않는다.
- `bodyShape`: 원문 체형 문자열. 앱의 새로운 진단으로 해석하지 않는다.
- `measurementTime`: 시:분:초 문자열. 시간대가 없으므로 UTC 변환이나 시간대 추정을 하지 않는다. 날짜는 기존 일자 키로 저장한다.
- PRO를 사용자가 확인한 경우 `trunkMuscleMass`/`trunkFatMass`로 저장한다. 이는 부위 배열과 몸통 아이콘에 따른 해석이다. 원문 `신체 근육량`/`체지방량`을 출처에 함께 남기며 골격근량이나 기존 일반 체지방량으로 치환하지 않는다. 미확인 기기는 이 두 항목을 저장 제외 참고값으로 유지한다.
- `metricSources`: 항목별 기기/양식, 원문 항목명·단위, 읽은 값의 표기, 입력 후 수정 여부, 매핑 버전을 보존한다. 연령은 OCR 원문 문자열도 보존한다. 숫자 값은 기존 숫자 저장 형식을 유지한다.
- 두 편집 화면 모두 자신이 편집하지 않은 항목을 보존한다. 간단 편집 화면은 추가 원문 기록을 읽기 전용으로 보여준다. 백업 및 동기화는 기존 JSON 구조를 사용하며 DB 스키마 변경은 없다.

## 검증 방식과 결과

| 단계 | 검증 |
| --- | --- |
| 원본 인식 | 두 원본 각각 숫자 27/27, 체형, 연령 단위, 날짜·시간 일치. 로컬 Tesseract 영문/한국어 모델 사용, 외부 요청 전송 0 |
| 의미 매핑 | 원문 30개 인벤토리, 표준체중/목표체중 분리, 원문 연령/기존 나이 분리, 몸통/골격근량 분리 |
| 확인 UI | 합성 전체 항목과 출처로 390px 대조표·입력값·넘침 검사, 읽지 못한 항목 표시 |
| 저장·재조회 | 합성 전체 항목을 확인 후 저장, 새로고침, 본 편집/간단 편집, 출처 수정 표시 유지 |
| 백업·동기화 | 실제 백업 다운로드 JSON과 동기화 snapshot/merge 직렬화에서 합성 전체 값·출처 일치 |
| 실제 OCR→UI | 합성 이미지와 실제 OCR 엔진으로 날짜/수치 수정, 충돌 확인, 저장, 재조회 통과 |
| 회귀 | 단위 753개, 기존 격리 UI 20개, 탭/초안 UI 10개, 전체 항목 보존 경로 6개 통과 |

타입 검사·수정 파일 린트·로컬 production build도 통과했다. 중간에 발견한 한국어 진단 서버 인코딩 문제와 간단 편집의 체중 출처 삭제 문제는 수정 후 해당 검사를 다시 통과했다.

전체 테스트의 기본 병렬 실행은 최초 753개 통과 후 최종 재실행에서 두 프로세스가 `Fatal process out of memory: Zone`으로 종료됐다. 같은 테스트 목록을 `--test-concurrency=2`로 재검증해 최종 753/753 통과, 실패·건너뜀 0을 확인했다. 중간의 메모리 종료는 기능 assertion 실패와 구분한다.

## 미검증과 반영 경계

- 실제 사용자 계정의 Preview/운영 저장·클라우드 왕복, 다중 기기 동시 수정, 기존 구버전 클라이언트의 재저장은 미검증이다. 구버전이 새 필드를 보존한다고 보장하지 않는다.
- 두 원본은 정확히 일치했지만 다른 OA 리포트 버전·기기·인바디 양식 전체를 지원한다는 뜻은 아니다. 고정 레이아웃 파서이며 최종 확인이 필요하다.
- 한국어 모델 로딩 실패 시 기존에 읽은 숫자는 유지하고 연령·체형을 직접 확인하도록 안내한다. 모델 파일 다운로드와 이미지 분석은 별개이며 건강자료를 외부 OCR 서비스에 보내지 않는다.
- 새 동작을 사용하려면 관련 로컬 소스 변경을 검토한 뒤 별도 승인으로 Preview에 반영해야 한다. 기존 PR 전체를 운영에 합치지 않는다.
