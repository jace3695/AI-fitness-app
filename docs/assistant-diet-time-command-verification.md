# 마지막 식사 시각 명령 검증 — 2026-09-16

## 지원 범위

- `오늘 마지막 식사 18:30 기록해줘` 또는 `오늘 마지막 식사 시각 18:30 저장해주세요`.
- 오늘(한국 시간)의 명시적인 24시간제 `HH:mm`만 받는다. 없는 날짜, 다른 날짜, 아직 지나지 않은 시각, `지금`·오전/오후 등 추정이 필요한 표현, 여러 작업을 섞은 문장은 저장하지 않는다.
- 15분 확인, 같은 탭의 확인 요청 복구, 저장 응답 유실 재시도, 공통 식단 실행 이력과 되돌리기를 연결한다.
- 식단 요약·끼니 상세·저녁 시각·공복 시작을 한 트랜잭션으로 맞춘다. 기존 화면의 정의에 따라 `dinnerBefore1830`만 입력 시각으로 계산하며 공복 성공·시간·달성 상태, 식사 완료, 물·영양값·메모는 보존한다.
- 공복 시작의 과거 원시 시각·JSON 시각·객체/JSON 날짜 지도 형식을 모두 읽는다. 새 저장은 오늘 날짜가 있는 객체로 기록하므로 다른 날짜에 오늘 시각을 재사용하지 않는다. 날짜 지도의 이전 날짜와 추가 필드는 유지하고 되돌리면 이전 원시 값을 그대로 복구한다.
- 캘린더의 공복 타이머도 같은 형식 판독기를 사용한다. 기존 원시 시각은 날짜 정보가 없으므로 과거 클라이언트와 동일하게 읽는다.
- 관련 일별 필드와 전체 공복 시작 값을 확인 당시/저장 직후 값과 비교한다. 공복 값에 다른 날짜가 추가됐어도 되돌리기는 보수적으로 중단한다. 다른 저장소의 다른 날짜는 보존한다.
- 기존 물·메모·단백질·밥량 확인/이력 형식과 초기화 잠금·소유자 RLS를 유지한다. 새 함수는 invoker, 빈 search_path, 인증 사용자 권한만 사용한다.
