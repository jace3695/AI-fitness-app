# 수분 총량·식단 메모 명령 — 2026-09-16

6단계의 식단 기록 명령 두 종류를 확인·실행 이력·되돌리기에 연결했다. 식단 전체 또는 6단계 전체 완료를 뜻하지 않는다.

## 지원 범위

| 명령 예시 | 저장할 내용 |
|---|---|
| `오늘 물 총 500ml 기록해줘` | 오늘 수분 총량을 500mL로 저장. 이전 값에 더하지 않음 |
| `오늘 물 총 0.5L로 저장해주세요` | 리터를 mL로 변환해 동일하게 총량 저장 |
| `오늘 식단 메모 추가: 점심 닭가슴살` | 기존 식단 메모 뒤에 줄바꿈과 입력 문장을 추가 |

- 연이 대화·빠른 명령 → 변경 전후와 한국 시간 날짜 확인 → 확인하고 저장 → 실행 이력의 식단 탭에서 조회·되돌리기.
- 수분 총량은 정수 0~10,000mL 범위의 입력을 받는다. 이 범위는 입력 오류 방지용이며 권장 섭취량이 아니다. 수분 저장소와 식단 요약의 `waterMl`·`water2l`을 한 트랜잭션으로 일치시킨다. 기존 값이 다르면 확인 화면에 둘 다 표시한다.
- `물 500ml 마셨어`처럼 추가량과 총량을 구분할 수 없는 말, 과거·미래 기록, 조건·질문·부정 표현은 저장하지 않고 지원 예시를 안내한다.
- 메모는 한 번에 400자, 추가 후 4,000자 이내다. 기존 메모는 교체하지 않으며 형식이나 길이를 확인할 수 없으면 중단한다. 메모 안의 `그리고`, `그거`, 할 일 명령 문구와 HTML 표기는 문자 그대로 저장·표시한다.
- 메모에서 음식량·칼로리·단백질을 추정하거나 식사 완료·공복·소화 상태를 채우지 않는다. 세부 영양·끼니 기록은 기존 식단 화면에서 입력한다.

## 보존·복구

- 로그인한 본인의 RLS와 invoker 함수로 두 저장소와 실행 이력을 원자적으로 갱신한다. 이력 저장 실패 시 식단 변경도 롤백한다.
- 확인한 오늘의 식단·수분 값과 초기화 표식을 비교한다. 다른 날짜·설정·식사 구성·단백질 기록은 유지하며, 오늘의 원본이 달라지면 오래된 확인 요청을 거절한다.
- 15분 확인 유효기간, 한국 시간 날짜 변경 방지, 동일 UUID 재시도, 응답 유실 뒤 같은 탭의 요청 복구를 적용한다. 저장한 요청은 만료 뒤에도 같은 결과를 조회하며 되돌린 요청을 재실행하지 않는다.
- 되돌리기는 같은 날짜의 현재 값이 저장 직후 값과 일치할 때만 수행한다. 이후 직접 편집한 식사를 덮어쓰지 않는다. 원래 없었던 날짜·저장소는 빈 값으로 남기지 않고 원래 부재 상태로 복구한다.
- 이전 JSON 문자열 저장 형식도 지원한다. 건드린 저장소의 공백·키 순서는 정규화될 수 있지만 날짜·값·문자열 형식은 보존한다. 메모 명령은 수분 저장소를 다시 쓰지 않는다.
- 식단 또는 비서 초기화 시 실행 이력을 지우고 대기 요청을 무효화한다. 계정 삭제는 외래키 cascade로 처리하며 Auth 내부 역할에 앱 테이블 권한을 추가하지 않는다.
