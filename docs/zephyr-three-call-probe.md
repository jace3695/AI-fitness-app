## 요청 범위와 준비한 코드

- `fix/app-wide-reliability`의 Vercel Preview에서만 `/assistant/voice-check`와 `/api/tts/probe` 사용 가능. 운영 환경과 다른 브랜치는 404.
- 현재 로그인 사용자 인증을 앱 서버와 Edge Function에서 각각 확인한다. 키는 기존 `GOOGLE_TTS_API_KEY`를 서버에서만 사용하며 화면에는 설정 여부만 표시한다.
- 미리 지정한 계정의 승인 요청 세 개만 사용. DB 슬롯 번호는 1~3으로 제한하며, 승인 기간은 최대 24시간이다. 앱과 Edge에서는 승인 생성·기간 연장·삭제를 지원하지 않는다.
- 고정 문장 61자, 총 최대 183자. `ko-KR-Chirp3-HD-Zephyr`, MP3, 요청당 Google 시도 1회. 접수 후 실패·응답 유실에도 동일 요청 번호 재사용 불가. 화면에서 오류가 나면 추가 생성을 멈춘다.
- 음성 생성 성공과 받은 음성의 재생 완료를 따로 표시한다. 재생 버튼은 받은 오디오만 사용한다.
- 월별 무료 승인과 원장, `FREE_MODE=true`, 일반 음성 기능은 변경하지 않는다. 실제 청구액을 0원으로 가정하지 않는다.

## 호스팅 적용과 자동 검증

- 마이그레이션 `20260915025439_zephyr_three_call_probe` 적용. 검증용 `zephyr_probe_slots` 테이블 하나와 내부 invoker 함수 두 개, JWT 필수 `zephyr-probe` Edge v1 ACTIVE를 확인했다. 파일과 테스트 참조를 실제 호스팅 이력 버전에 맞췄으며 SQL 본문은 같다.
- 해당 테스트 계정에만 세 슬롯을 한 시간 동안 승인했다. 이미 접수한 슬롯은 기간이 지나도 재사용할 수 없다. 앱·Edge에는 슬롯 재생성/삭제/한도 초기화 기능이 없다.
- RLS 활성화, 일반 사용자 테이블 조회/RPC 실행 불가, service role도 슬롯 생성·만료 연장·삭제 불가를 확인했다. [RLS 정책 없음 INFO](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy)는 일반 사용자의 직접 접근을 막는 의도한 설정이다. 기존 [유출 비밀번호 보호 WARN](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection)은 별개이며 설정을 변경하지 않았다. 새 테이블의 성능 진단 항목은 없었다.
- 월별 무료 승인 0건·일반 음성 예약 0건 유지. 기존 지출 36건·기존 AI 사용 이력 13건도 같은 행 수를 유지했다. 이번 작업에서 기존 개인 기록의 내용을 수정하지 않았으며, 전체 행 해시 대조를 새로 수행한 것으로 주장하지 않는다.
