# 분석 이력 DB 적용 전 검토 범위

아직 적용을 요청하거나 실행하지 않았다. 아래 대상 확인과 별도 승인이 먼저 필요하다.

## 정확한 대상 확인 상태

- 앱 저장소: `jace3695/AI-fitness-app`, 후보 기준 `a08d9cf6b8cebf41dbc74916aa675fc25d61636b`.
- 서비스: 앱 서버의 `NEXT_PUBLIC_SUPABASE_URL`이 가리키는 Supabase 프로젝트.
- **후속 메타데이터 읽기에서 활성 프로젝트 Jace App Hub, ref piqqukiiacncfbztktga, 서울 리전을 확인했다.** 기존 운동/일본어/가계부/비서 테이블과 RLS 활성 상태가 있으나 public.body_analysis_history는 없다. 비활성 AI 가계부 프로젝트 vzcehalhihtdruetecvb도 목록에 있어 이름만으로 실행 대상을 선택하면 안 된다. 실제 Preview와 활성 프로젝트의 연결은 아직 확인하지 않았다.
- 최초 로컬 조사에서는 프로젝트 이름/참조 ID를 확인하지 못했다. `supabase/.temp/project-ref` 파일은 없고, 루트의 환경 파일에는 `.env.example`의 `your-project-ref.supabase.co`만 있다. 예시 값을 실제 대상으로 사용하면 안 된다. Preview와 운영이 같은 DB인지도 미확인이다.
- 승인 전 담당자가 실제 Preview의 프로젝트 ref와 이름, 운영 공유 여부를 명시해야 한다. 서비스 환경변수·비밀 키·보안 설정을 이 작업에서 조회하거나 변경하지 않았다.

## 제안하는 데이터베이스 변경

`schema-draft.sql`의 신규 `public.body_analysis_history` 테이블 하나, 소유자/시각/ID 복합 정렬 인덱스 하나, 소유자 SELECT/INSERT/DELETE 정책 세 개다. 기존 테이블·열·정책·함수·개인 기록은 수정하지 않는다. `auth.users`에는 삭제 cascade 참조만 추가하며 계정을 생성/삭제하지 않는다.

- 열: `user_id uuid`, `id uuid`, `snapshot jsonb`, `created_at timestamptz default now()`.
- `(user_id,id)`가 기본키다. 같은 요청 재시도는 기존 내용을 조회해 일치할 때만 성공한다. 같은 ID의 내용 변경은 거부한다.
- RLS 활성, public/anon 권한 없음. authenticated는 자기 행 조회/삭제 및 id/user_id/snapshot 삽입만 허용한다. UPDATE와 생성 시각 지정 권한은 없다. service_role을 클라이언트에 전달하지 않는다.
- 스냅샷은 고정 규칙 분석문·기준일·출처/버전으로 한정한다. 사진/원본 기록/전체 대화의 자동 적재나 backfill은 없다. 처음 생성 시 0행이며 사용자 확인 저장 전에는 행을 만들지 않는다.
- API는 사용자 인증과 예상 계정 일치를 검사한다. DB 직접 접근은 UI의 동의 체크박스 자체를 증명하지 않으므로 이 필드를 법적 동의 감사 로그라고 주장하지 않는다.

## 보존과 삭제

분석문은 운동/비서 초기화와 별도로 보관한다. 저장 전 설명과 두 초기화 화면의 유지 항목에 이를 명시했다. 분석 이력 화면에서 개별 확인 삭제하거나 계정 삭제 시 cascade로 삭제된다. 삭제 API는 해당 사용자+UUID 한 행만 대상으로 하며 원본 체성분/운동/대화 기록은 건드리지 않는다. 일반 대화 전체 이력 기능과 다르다.

## 검증·되돌리기 제안

별도 승인 후 폐기 가능한 계정 두 개와 합성 분석문만 사용해 저장→새로고침→조회→같은 ID 재시도→타 계정 조회/삭제 거부→지정 테스트 행 삭제를 검증한다. 실제 개인 건강 기록과 백업은 사용하거나 정리하지 않는다. 외부 AI/음성 호출·유료 호출은 필요 없다.

실패 시 먼저 이 기능의 앱 노출/배포를 이전 코드로 되돌리고 새 테이블은 유지한다. 테이블 삭제는 저장된 분석문을 파괴하므로 자동 rollback에 넣지 않는다. 새 테이블이 비어 있음을 승인된 검사로 확인하거나 별도 보존·삭제 승인을 받은 경우에만 신규 정책/인덱스/테이블 제거 범위를 따로 결정한다. 기존 테이블/백업 삭제는 포함하지 않는다.

CLI의 작업공간 밖 `.supabase` 생성 EPERM은 재시도하지 않았다. 이 파일은 공식 migration 적용 기록이 아니다. 이번 후속 리뷰에서는 SQL을 실행하지 않았다.

## 후속 확인: 승인 없이 테스트 기록도 삭제하지 않음

개별 삭제는 앱에서 복구할 수 없다. 따라서 검증용 합성 기록이라도 실제 서비스에 생성한 기록의 정리를 자동 실행하지 않는다. 테스트 계정·생성할 행·삭제할 UUID 범위와 영구 삭제를 사용자가 명시적으로 승인한 뒤에만 정리할 수 있다. 원본 개인 기록·기존 백업은 해당 승인에 포함하지 않는다.

Vercel 메타데이터에서 `NEXT_PUBLIC_SUPABASE_URL` 한 항목이 `preview`와 `production`을 함께 대상으로 함을 확인했다. 별도 브랜치 지정은 없었다. 값은 sensitive로 표시돼 복호화하거나 읽지 않았다. 따라서 두 환경의 공통 설정 항목이라는 점만 확인했으며, 실제 URL의 프로젝트 ref 및 이미 배포된 각 버전의 환경 스냅샷 일치 여부는 미확인이다. 환경변수 변경·내려받기·키 출력은 하지 않았다.
