# 루틴의 명시적 쉬움 응답과 다음 목표 검토

작성: 2026-10-10 KST / 2026-10-09 UTC. 현재 작업 트리의 제한된 구현 및 로컬 검증 기록이며 운영·브라우저 acceptance 완료 보고가 아니다.

## 원문과 범위

원본 「AI 연이 앱 개선 로드맵」 p9, 루틴 P1 「난이도 자동 조절」의 “너무 쉬우면 다음 단계”에 해당한다. 기존 중단 이유·반복중단 축소·오늘 3개·요일/주간 목표·운동 연결은 재구현하지 않는다.

기존 루틴 모델의 변경 가능한 목표는 분 단위 시간이므로, 이번 단계는 **현재 시간 목표에서 작은 다음 시간 목표를 검토하는 경로**다. 새 학습 단계 분류, 교재/교육과정 난이도 판정, 운동 중량·반복수 조정 또는 건강 판단을 구현했다고 주장하지 않는다.

## 선택형 기록

- 진행 중 루틴 및 지난 완료 기록에 선택형 난이도 입력을 추가한다: 너무 쉬웠어요 / 적당했어요 / 어려웠어요 / 선택 안 함.
- 완료 기록의 기존 `growth_sessions.metrics.routineDifficulty` JSON 키로 저장한다. 진행/중단 기록에는 기존 `stopReason`만 저장한다.
- 선택 안 함은 새 난이도 키를 만들지 않는다. 빠른 완료·기존 완료 횟수·타자 정확도 등으로 쉬움을 추정하지 않는다.
- 누락·알 수 없는 과거 값은 미기록으로 표시하고 계산에서 제외한다. 기존 행과 다른 metrics 키를 수정하지 않는다.
- 최근 기록에서 난이도를 다시 보여준다. 현재 화면의 저장 실패에서는 선택을 유지하고 성공 이후 다음 기록은 미선택으로 시작한다.

## 공개된 앱 규칙

최근 14일(오늘 포함) 안에 동일 소유자·동일 루틴에서 다음 조건을 만족할 때만 제안한다.

1. 현재 목표와 같은 `planned_minutes`이고 실제 기록 시간이 현재 목표 이상인 완료 기록.
2. 사용자가 `too_easy`를 직접 고른 서로 다른 날짜가 최소 3일. 같은 날 여러 기록은 날짜 하나로 센다.
3. 같은 14일에 진행/중단 기록이 있으면 상향을 보류한다. 현재 목표에서 적당함/어려움 응답이 있어도 보류한다.
4. 새 목표는 현재 목표 +5분, 기존 상한 240분 이내. 비활성 루틴에는 제안하지 않는다.

3일·14일·최대 5분은 보수적으로 정한 앱 규칙이다. 과학적으로 입증된 최적 학습량이나 운동 처방을 뜻하지 않는다. 완료 횟수만으로 올리거나 자동으로 적용하지 않는다.

## 미리보기·적용·이력 보호

- 기존 주간 코칭 화면/저장 JSON을 재사용하며 현재→제안 시간과 정확한 응답 날짜를 표시한다. 원래 목표 시간, 루틴 수정 시각, 근거 날짜와 세션 ID를 제안에 보존한다. 기존 제안 JSON의 8,000바이트 한도를 지키도록 최근 3개 서로 다른 날짜에서 날짜별 세션 ID 하나를 결정적으로 고른다. 이후 쉬움 기록이 더 생겨도 원래 3일의 근거가 유효하면 기존 미리보기를 무효화하지 않는다.
- 체크만으로 변경하지 않는다. 현재 유지 또는 선택한 제안 적용을 명시적으로 눌러야 기존 `decide_growth_review` 트랜잭션이 실행된다.
- 저장된 제안과 현재 목표/수정 시각이 다르거나 근거가 사라졌으면 적용하지 않는다. 적용 직전 현재 소유자의 최근 기록을 다시 읽는다. 읽기 실패도 적용을 막는다.
- 기존 RPC의 루틴 수정 시각 비교·결정 및 목표의 원자적 저장·같은 결정 재시도 보호를 유지한다. 추가 migration의 서버 검증으로 클라이언트 재조회 이후 사라지거나 바뀐 근거도 트랜잭션 안에서 거부한다. 자세한 잠금 순서와 적용 의존성은 아래와 같다.
- 적용 후 계정, 저장 결정, 선택 ID와 목표를 다시 조회해 확인한 뒤에만 성공 안내를 한다. 결과를 확인하지 못한 경우 불확실성을 표시하며, 다음 재조회에서 이미 저장된 결정을 보여준다.
- 같은 근거로 새 목표를 다시 올릴 수 없다. 새 목표에서는 이전 `planned_minutes`가 맞지 않기 때문이다. 이미 결정한 코칭은 다시 적용할 수 없다.
- 최신 및 지난 코칭 결정에서 원래 제안과 날짜를 확인할 수 있다.
- 기존 선택형 AI 경로가 추후 켜져도 집계 횟수만으로 새로운 상향을 만들어 적용할 수 없게 필터링한다. 검증된 로컬 다음 목표 제안을 그대로 유지한다. 필터링 후 모델 제안이 모두 사라지는 경우에도 기존 로컬 목표 축소/짧게 시작 제안으로 대체한다. 새 API나 AI 호출은 만들지 않았고 실제 유료 호출은 하지 않았다.

## 원자적 서버 검증과 적용 의존성

`supabase/migrations/20261009190454_validate_growth_progression_evidence.sql`은 `decide_growth_review(uuid,jsonb,jsonb)` 하나를 교체하는 추가 migration이다. 새 테이블/컬럼/트리거/RLS/환경설정이나 권한 확대는 없다. 기존 `SECURITY INVOKER`, 빈 `search_path`, 함수 서명과 실행 권한을 유지한다. hosted DB, 실제 개인 기록, Production, 외부 배포를 조회하거나 변경하지 않았다.

- 새 `progression` 메타데이터 또는 `local-next-step-` ID를 가진 선택 항목만 새 근거 검증을 받는다. 기존 다른 제안의 적용 방식과 시간은 바꾸지 않는다.
- 소유자별 기존 기록 초기화 advisory 잠금 → 코칭 행 → ID 순서의 선택 루틴 행 `FOR UPDATE` → ID 순서의 해당 루틴 세션 행 `FOR SHARE NOWAIT` 순으로 잠근다. 예전 세션이 최근 날짜로 옮겨지는 경우도 고려하여 해당 루틴의 모든 기존 세션을 잠근다. 루틴 행 잠금은 외래키 검사 잠금과 충돌하여 새 연결 세션의 삽입/이동과도 직렬화한다.
- 직접 세션 수정이 먼저 잠갔으면 기다리며 역순 잠금을 만들지 않고 재조회 후 재시도하라는 `40001` 오류로 전체 변경을 거부한다. 대상·결정 중 일부만 저장하지 않는다.
- 서버의 Asia/Seoul 날짜를 기준으로 오늘부터 13일 전까지를 포함한다. 저장한 고유 ID들이 동일 소유자/루틴의 현재 목표 완료·충분한 실제 시간·명시적 `too_easy` 기록인지, 그 ID들의 서로 다른 날짜가 저장된 날짜와 정확히 맞는지 검증한다. 현재 목표/수정 시각, +5분 및 240분 상한, 최근 중단/진행/현재 목표의 적당함·어려움도 다시 확인한다.
- 이미 저장한 동일 선택의 재시도는 근거를 다시 해석하기 전에 원래 결정을 반환한다. 적용 후 근거가 삭제되거나 목표가 별도로 바뀌어도 재시도가 목표를 다시 쓰지 않는다. 현재 유지는 상향 근거가 없어도 가능하다.
- 이 migration은 새 상향 기능을 활성화하기 전에 적용되어야 한다. 이전 RPC만 설치된 환경에서는 클라이언트의 사전 조회만으로 조회→적용 사이의 변경을 막을 수 없다. 이번 작업은 파일 작성 및 로컬 PGlite 검증이며 hosted 적용 완료가 아니다.

잠금 설계는 [PostgreSQL 행 잠금 문서](https://www.postgresql.org/docs/current/explicit-locking.html)의 충돌 규칙을 기준으로 검토했다. 별도 연결을 사용한 실제 PostgreSQL의 잠금 대기·NOWAIT·동시 삽입/이동·초기화 경합 검증은 아직 하지 않았다. PGlite 테스트를 그 검증의 대체로 보고하지 않는다.

기존 브라우저 EPERM 제한을 우회하거나 다시 실행하지 않았다. 정확한 통합 후보에서 격리된 Chromium/WebKit 실제 실행, 작은 화면과 저장 후 재조회, 오류 안내, 계정 전환을 확인하기 전까지 이 변경의 브라우저 acceptance는 미완료다. 이 단계의 담당 및 독립 검토 작업은 전체 build/전체 회귀를 실행하거나 커밋·push·CI 취소를 하지 않았다.
