# 일본어 추가 기능 로컬 인계 — 2026-10-21

## 범위와 접근 결과

원본 `AI-fitness-app` HEAD `a08d9cf6b8cebf41dbc74916aa675fc25d61636b`를 정식 승인 경로에서 읽었다. 최초 샌드박스 읽기는 Permission denied로 실행되지 않았고, 사용자의 새 승인 후 재시도는 성공했다. 원본의 수정 중인 파일은 복사하거나 편집하지 않았다. 허용 작업공간의 `japanese/`에는 기준 커밋의 개발 코드만 추출했다. `.env`, 키 파일, 인증정보, public 원본 자산, 미추적 사용자 파일은 복사하지 않았다. 기존 개발 의존성을 읽어 복사했으며 네트워크 설치·push·배포는 하지 않았다.

기존 문서 `japanese-conversation-local-review.md`, `japanese-beginner-focus-verification.md`, `roadmap-1-9-verification.md`와 일본어 화면·API를 읽었다. 전체 목표는 자유 AI 회화, 학습 기록, 복습, 발음 지원을 포함한다. 이번 패치를 전체 목표 완료 또는 10월 25일 완료 보장으로 취급하지 않는다.

## 구현한 부분

- `/language/practice`: 자유 문장 입력, 상황 구분, 계정별 현재 탭 기록 최대 30개, 새로고침 복원, 복습 표시·필터, 직접 재연습 횟수, 개별 삭제. 기존 영구 저장·클라우드 학습 기록과 명확히 구분한다. `sessionStorage`만 사용하며 다른 기존 학습 키를 수정하지 않는다.
- 손상된 기록은 덮어쓰지 않고 입력을 잠근다. 사용자가 검토 후 이 탭의 기록만 삭제할 수 있고 취소하면 보존한다. 저장 공간 실패 시 입력 유지.
- 자유 AI 대화 UI와 주입 가능한 전송 계약: 같은 상황의 성공한 최근 4쌍만 문맥, 입력 1000자·응답 필드 4000자 제한, 동시 요청 억제, 20초 제한, 취소·화면 이탈·늦은 응답 보호. 성공한 응답은 입력과 한 쌍으로 보관한다.
- `service.ts`: 기존 인증 헤더를 주입받는 HTTP 어댑터. 401/402/429/503 및 일반 실패를 구분하고 자동 재시도하지 않는다. **실제 페이지에 연결하지 않았다.**
- `Recorder.tsx`: 사용자 버튼으로만 녹음 요청, 최대 30초, 메모리 재생, 삭제, 권한 거부·지원 없음 안내, 취소 후 늦은 권한 응답의 트랙 종료, 문장 변경·탭 숨김·이탈·계정 변경 시 정리. 녹음 업로드·저장·STT·발음 점수 생성 없음.
- 기존 회화·말하기 화면에 진입 링크 추가. 말하기 정답 수가 자기 보고이며 AI 발음 점수가 아님을 명시.

## 아직 활성화하지 않은 기능과 계약

`lib/free-mode.ts`는 `FREE_MODE=true`이며 유료 AI는 명시적 후속 코드 변경 전까지 차단하는 정책이다. 이를 변경하지 않았다. 신규 화면은 AI 버튼이 비활성 상태이며 서비스 연결 대기를 표시한다. 기존 `/api/language/conversation`은 서비스 불가 시 고정 예문을 반환하고 응답 출처 필드도 없다. 신규 파서는 이를 AI 응답으로 표시하지 않고 거절한다.

후속 서버 연결 시 다음 사항이 필요하다. 이 문서는 변경 제안이며 현재 서버·보안·DB를 수정한 결과가 아니다.

1. 서비스·모델·비용 상한·데이터 전송에 대한 승인 후 기존 AI 예산 정책과 인증을 유지해 서버를 연결한다. API 응답은 실제 생성 성공 시에만 `{ source: 'ai', reply, replyReading, correction, explanation }`를 반환한다. 고정 예문/연결 불가를 `source:'ai'`로 바꾸면 안 된다. 미연결은 503, 인증 실패 401, 예산 한도 402, 속도 제한 429로 처리한다.
2. 서버에서 상황 allowlist, 입력 1~1000자, 최근 8개 메시지의 역할·문자열·크기, 전체 요청 크기, 모델 출력 스키마를 검증한다. 응답이 잘렸거나 파싱 실패하면 오류를 반환하고 임의 답변/교정으로 성공 처리하지 않는다. 클라이언트 검증은 서버 검증을 대체하지 않는다.
3. 위 계약 검증 뒤 `PracticeWorkspace`에 `conversationTransport(fetch, authenticatedJsonHeaders)`를 전달한다. 응답 출처를 증명할 수 없는 기존 API에는 지금 연결하지 않는다. 클릭 취소는 클라이언트 대기를 중지하며 이미 시작한 외부 처리의 비용 취소를 보장하지 않는다.
4. 영구 학습 기록은 별도 승인된 데이터 모델·삭제/초기화 정책·계정 격리·중복 방지 키·충돌/재시도 설계가 필요하다. 현재 탭 보관을 계정 동기화 완료로 보고하지 않는다. 기존 문장 복습 저장은 그대로 유지했다.

## 검사 결과와 한계

- 단위/계약: 신규 8개 + 기존 고정 회화 8개 = **16개 통과**. 모델은 호출하지 않았고 HTTP도 주입한 합성 함수다.
- 신규 브라우저: **10개 흐름 통과**, pageerror 0, 외부 요청 시도 0. 실제 컴포넌트 + 합성 인증/AI/마이크 + 로컬 HTTP. 새로고침, 복습/재연습, 삭제/취소, 계정 변경, 실패/취소/시간 초과, 저장 실패/손상 복구, 30초 녹음 종료·이탈 정리 포함.
- 기존 회화/복습 브라우저: **16개 흐름 통과**. 5개 상황과 10개 후속 선택지, 복습 저장·재조회·계정 분리, 음성 취소 회귀를 합성 인증·음성으로 확인했다. 첫 시도는 사본의 `next/image` 개발 의존성 누락으로 번들 실패했고 기존 개발 패키지를 보충한 뒤 재검사했다.
- 320px 스크린샷 직접 확인: 줄바꿈·버튼·입력·안내 표시. 공통 레이아웃 전체나 물리 기기 검증은 아니다. 최초 화면 검사에서 검사기 CSS 변수가 누락되어 버튼 글자가 안 보였고, 실제 공통 CSS를 포함해 다시 검사했다.
- 변경 TS/TSX ESLint 통과. 독립 신규 모듈 6개(`conversation.ts/test`, `service.ts/test`, `Recorder.tsx`, `PracticeWorkspace.tsx`)의 strict TypeScript 검사 통과. 계정 래퍼는 브라우저 번들/합성 인증 검사 및 lint 대상이다. 전체 앱 타입/빌드 검증 완료를 주장하지 않는다.
- 최초 Edge 샌드박스 실행은 시작 직후 종료. 정식 승인 경로의 localhost 검사 성공. 원본/보안 설정 변경 없음.
- 실제 Auth/DB/동기화, AI 품질·청구, 실제 마이크·녹음 재생 품질, Safari/iPhone, 전체 Next.js 라우팅/레이아웃 빌드는 미검증이다. 새 마이크 권한을 수락하거나 실제 계정 기록을 수정하지 않았다.

## 통합

이 작업은 원본 저장소와 Git 이력이 연결되지 않은 제한된 코드 사본이다. **초기 스냅샷 커밋을 병합하지 않는다.** 제공하는 최종 변경 패치를 통합 담당자의 별도 후보 작업공간에서 `git apply --check <patch>`로 먼저 검사한 뒤 적용한다. 변경은 `app/language`와 일본어 전용 검사·문서뿐이며 공통 레이아웃·캐릭터·운동·가계부·비서는 수정하지 않았다.

통합 뒤 기존 의존성이 갖춰진 후보에서 전체 타입/lint/build, 일본어 기존 회화 검사, 신규 검사, 실제 Next.js 경로 이동을 확인한다. 이 로컬 패치는 외부 서비스 활성화·DB 변경·배포 승인을 포함하지 않는다.
