## 확인 방법

[음성이 포함된 미리보기](Yeoni_Lip_Sync_Dev_Preview.html)를 내려받아 브라우저에서 연다.
**저장된 연이 음성 불러오기 → 재생**을 누른다. 5.376초 기존 MP3를 재사용한다.
새 TTS 요청·외부 업로드·계정 변경은 없다. 자동 정렬 초안임을 화면에 표시한다.
화면 아래에서 닫힘/아/이/우/에/오를 멈춘 상태로 비교할 수 있다.
무음 기술 샘플은 별도 버튼이며 실제 음성 결과로 취급하지 않는다.

## 구현

- `CharacterController`: 재생 상태·현재 시각·표시 정책 → 불변 `CharacterFrame`.
  DOM/React/Canvas/HTMLAudioElement 의존이 없고 별도 발화 타이머도 없다.
- `LipSyncPlayer`: 오디오 수명·해시 검증·재생 이벤트를 처리하고 일반 `PlaybackSnapshot`만 전달.
- `character-stage.ts`: 최대 30fps의 한 루프와 가시성·입력·모달·동작 줄이기 정책.
  외부 Controller 주입을 지원한다. `cat-renderer.ts`는 의미 프레임을 Canvas에 그린다.
- 닫힘/아/이/우/에/오의 여섯 도형과 자음용 `small`을 구분한다. 인간형·Rive/Live2D는
  같은 프레임 계약을 사용할 수 있으나 해당 어댑터를 구현한 것으로 보고하지 않는다.
- 실제 음성·확정 발화문 SHA-256을 묶은 60개 음소 구간. 미지원 음소·겹친 시각·잘못된 파일은 거절.
  자동 정렬 상태 `automatic-phonemes`를 추가했고 기존 v1 필드 의미는 유지한다.

## 정렬 결과와 한계

[MFA 실행·변환 재현 방법](alignment/README.md), [출처·파일 해시](alignment/provenance.json),
[원시 결과](alignment/mfa-phrase.raw.json), [재생용 타임라인](fixtures/zephyr-ko-39.timeline.json).
MFA 3.4.2와 Korean acoustic v3.0.0을 앱과 분리된 개발 환경에서 실행했다.
원본 MP3를 그대로 재생하고 분석용으로만 16kHz PCM으로 디코딩했다. 잘라내기·속도 변경·새 생성 없음.

기본 사전 실행의 OOV는 0이었으나 형태소 경계에서 오늘은의 연음, 일정을/드릴게요의 된소리,
좋겠어요의 거센소리·연음이 충분히 반영되지 않았다. 이번 9개 어절의 표준 발음 가설을 명시한
사전으로 다시 정렬했다. 시각은 모두 음향 모델 결과이며 글자별 균등 분할이나 임의 보정이 아니다.
이 사전은 범용 한국어 G2P 구현이 아니며 실제 발음과 경계는 청취 확인이 필요하다.

특히 ‘쉬는’ 경계는 두 정렬 결과 차이가 커서 우선 검토 대상이다. 둥글림 `/sʷ/`는 30ms로
한 프레임보다 짧을 수 있다. 이를 길게 늘려 검증된 것으로 꾸미지 않았다. 독립된 ㅜ 모음과
ㅂ/ㅍ 폐쇄, 숫자, 긴 문장 등은 이 39자 녹음으로 검증하지 못했다. 추가 TTS 생성은 하지 않았다.

## 검증 상태

- 전체 단위 검사 686개, 린트·타입 검사·Next.js 빌드: 이번 코드에서 확인.
- 로컬 Chromium: 기존 기본 움직임 16개 + 새 립싱크 21개 시나리오 통과.
- 실제 MP3를 처음부터 끝까지 재생하고 60개 구간 선택, 문장 사이 무음·종료,
  탐색·일시정지·재개를 확인. 320/390/430/1280px, 어두운 배경, 여섯 도형 정지 비교 포함.
- 실제 음성 검사에서 렌더 프레임과 음소 구간 선택 불일치 0. 오디오 현재 시각 대비 그리기 때
  읽은 시각의 차이 p95 약 33.5ms, 최대 약 35.5ms. **음소 정렬 오차나 스피커 지연 측정값은 아니다.**
- 로컬 WebKit은 시스템 라이브러리 부족으로 실행 불가. 설치도 실행 환경 권한 제약으로 실패했다.
  동일 소스의 GitHub Actions WebKit 결과를 별도 확인한다. 과거 CI 통과를 이번 변경의 통과로 재사용하지 않는다.
- 사람이 듣는 발음 경계·입 모양 자연스러움, 물리 iPhone/잠금/Bluetooth는 미검증.
  합성 hidden/waiting 이벤트 검사를 실기기 검증으로 확대하지 않는다.

운영 main은 #206, 개발은 [draft PR #207](https://github.com/jace3695/AI-fitness-app/pull/207).
운영 병합·배포는 하지 않는다. 그림 연습 실사용 보류와 분석 SQL 방 후속 완료 미확인 상태를 유지한다.
사용자가 음성이나 JSON을 만들 필요는 없다. 청취 검토 후 PHASE 5 완료 여부를 판단한다.
