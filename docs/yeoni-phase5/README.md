# PHASE 5 — 고양이 한국어 립싱크: 재생 기반 구현, 실제 음성 검증 대기

작성일: 2026-09-29 (한국시간). **PHASE 5 전체 완료가 아니다.** 현재는 입 모양과
오디오 시계 동기화를 구현했다. 실제 Zephyr 한국어 음성에 음소를 정렬하고 소리를
들으며 자연스러움을 검증하는 작업이 남아 있다. 전체 16단계 중 4단계 완료를 유지한다.

## 이번에 구현한 범위

| 파일 | 기능 |
| --- | --- |
| `lib/yeoni/lip-sync.ts` | 한국어 음소→입 모양, 시각 검색, 타임라인 검증, 음성·발화문 SHA-256 대조 |
| `lib/yeoni/lip-sync-player.ts` | 실제 오디오 위치 기반 재생·정지·탐색·배속·오류·백그라운드 처리 |
| `lib/yeoni/cat-mouth.ts` | 닫힘·작게 열림·크게 열림·둥근 입·가로형 입 |
| `components/yeoni/CatAnimationStage.tsx`, `lib/yeoni/cat-renderer.ts` | 기존 렌더러에 선택적 입 모양 연결, 프레임별 React 갱신 없음 |
| `public/yeoni/cat/poc-speech-atlas-v1.png` | 기존 고양이 몸에서 고정 입만 제거한 별도 자산 |
| `scripts/yeoni-speech-poc/` | 독립 화면, 실제 파일 입력, 브라우저 검증, 오프라인 내보내기 |
| `.github/workflows/yeoni-animation-review.yml` | 기존 기본 움직임과 새 음성 시계 검증을 Chromium·WebKit에서 실행 |

입 크기를 음량이나 글자 길이로 추정하지 않는다. 이미 정렬된 실제 음소 시각을
입력받아 `audio.currentTime`으로 검색한다. 파일 교체 시 이전 비동기 결과를 버리고,
무음 구간·정지·끝·오류·버퍼 대기에는 입을 닫는다. 백그라운드에서 음성을 멈추며
복귀 후 자동 재생하지 않는다. 파일과 발화문의 해시, 구간 순서와 길이를 검증한다.
검토 상태 필드는 입력자의 선언이며 실제 정렬 정확도나 음성 출처를 인증하지 않는다.

새 운영 연결·TTS 호출·유료 서비스·DB·인증 변경은 없다. 운영 main은 #206 반영 상태,
이 개발 작업은 [draft PR #207](https://github.com/jace3695/AI-fitness-app/pull/207)에 둔다.
인간형 A안과 그림 연습 실사용 보류 상태는 유지한다. 분석 SQL 방의 후속 완료는
이번 단계에서 확인하지 않았으므로 계속 미확인이다.

## 직접 보기

[Yeoni_Lip_Sync_Dev_Preview.html](Yeoni_Lip_Sync_Dev_Preview.html)을 다운로드해서
브라우저에서 열고 **무음 동작 샘플 불러오기 → 재생**을 누른다.
내장 샘플은 8초 무음 WAV와 인위적인 음소 구간이다. **한국어 음성 시연이 아니며,
이 결과로 발음 정렬 정확도를 주장하지 않는다.** 실제 음성·타임라인 쌍을 선택하는
입력도 있다. 입력 파일은 외부로 전송·저장하지 않고 새로고침하면 제거된다.

## 발견한 문제와 남은 조건

1. 프로젝트의 TTS 응답은 MP3만 반환하며 음소 타임라인이 없다. 작업 파일에도 재사용할
   Zephyr 한국어 녹음이 없어 실제 음성 정렬·청취 검증을 진행하지 못했다.
2. 한국어용 Montreal Forced Aligner 모델을 대안으로 조사했다. 실제 Zephyr 파일을
   확보한 뒤 실행·발음 사전/음소 변환·경계 검수를 해야 하며 현재 실행 성공을 주장하지 않는다.
3. 첫 배속 검사에서 250ms 벽시계만으로 오디오 진행량을 판정하면 브라우저의 재생 버퍼
   전환 지연을 혼동했다. 목적에 맞게 2배속 상태에서 **실제 재생 시각과 두 입 모양 구간의
   일치**를 확인하도록 고쳤다. 정렬 정확도나 지연 성능을 검증한 것으로 보고하지 않는다.
4. 자산은 PoC용이다. 확대 시 미세 가장자리와 실제 발화 중 입 모양 자연스러움은 후속 검토가 필요하다.

## 다음 작업에 필요한 자료

개인 기록이 포함되지 않은 **기존 Zephyr MP3 또는 WAV와 실제 읽은 문장**이 필요하다.
권장 문장은 “안녕하세요. 오늘 일정을 알려드릴게요. 오늘은 조금 쉬는 게 좋겠어요.”다.
타임라인 제작은 개발 작업으로 이어서 수행한다. 사용자가 JSON을 작성할 필요는 없다.
이 자료로 정렬·청취·브라우저 재생을 확인한 다음 PHASE 5 완료를 판단한다.
그 전에는 PHASE 6 완료나 운영 병합·배포로 넘어가지 않는다.
