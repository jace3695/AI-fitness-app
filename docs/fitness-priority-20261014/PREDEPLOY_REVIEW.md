## 1. 인바디 저장 날짜

- OA 긴 리포트의 인식 날짜를 별도 가져오기 초안의 기본 날짜로 사용한다. 날짜와 수치를 화면에서 수정하고 **확인한 날짜로 저장**을 눌러야 저장한다. 다른 인바디 양식 전체 지원이나 OCR 정확도 개선이 아니다.
- 날짜 없음, 미래 날짜, 달력상 존재하지 않는 날짜는 빈 날짜로 표시하고 저장을 막는다. 달력에서 현재 선택한 날짜를 대신 사용하지 않는다. 숫자는 남아 있고 사용자가 날짜를 지정하면 저장할 수 있다. 수치 인식 자체가 0개라면 오류 안내 후 가져오지 않는다.
- 저장 직전에 해당 날짜의 최신 로컬 기록을 읽는다. 체중 또는 인바디 기록이 있으면 브라우저 확인창을 띄운다. 취소하면 아무것도 쓰지 않는다. 인식한 값과 직접 수정한 값만 반영하고 다른 값과 대상 날짜의 메모를 보존한다. 직접 빈칸으로 지운 값은 삭제 의도로 처리한다. 확인 중 계정/저장 내용이 바뀌면 다시 검토하도록 실패시킨다.
- 완료된 초안은 달력을 바꿔도 유지한다. 아직 처리 중인 OCR은 날짜 이동, 계정/세션 epoch 변경, 화면 해제 시 무효화한다. 완료된 초안도 계정 전환 시 폐기한다. 저장 실패 시 초안은 유지한다.
- 저장 날짜로 달력 날짜/월을 이동한다. 다른 운동/메모 편집 초안이 있으면 그 초안을 버리지 않도록 달력 이동만 생략한다. 실제 저장 날짜는 확인한 날짜다.
- 계정/인증/클라우드 동기화 구현, 서버 스키마, RLS 정책, 저장 키는 변경하지 않았다. 기존 계정 소유자·epoch 표식과 이벤트를 읽고 기존 로컬 저장 트랜잭션을 사용한다. 실제 계정 전환/클라우드 왕복 검증과 로컬 이벤트 모사는 별개다.

## 3. 사람형 동작 도해: 벽 푸시업 1개

`WallPushupDemo.tsx`와 `wallPushupMotion.ts`는 이번 작업에서 코드로 직접 그린 SVG다. 외부 그림/영상/경쟁 앱 자산/모션 파일을 복제하거나 다운로드하지 않는다. 기존 벽 푸시업과 source ID가 보존된 커스텀 벽 푸시업에만 표시한다. 다른 운동에 같은 애니메이션을 재사용하지 않는다.

기본 정지, 재생/일시정지, 반복 선택, 0.5배속, 위치 슬라이더, 시작/굽힌 정지 자세, 항상 보이는 정지 텍스트 안내를 제공한다. 숨겨진 탭에서는 정지한다. 동작 감소 설정에서도 자동 재생하지 않는다.

검증 범위: 한 주기 101개 표본에서 손·발 접촉점 고정, 팔 두 구간 길이 유지, 몸통 직선, 머리의 벽 관통 없음, 유한 좌표, 주기 시작/끝 일치를 확인했다. 브라우저 시작/굽힘/복귀 스크린샷을 직접 검토했고 제어 동작을 테스트했다. 기본 벽 접촉/어깨 높이 손 배치는 [The Stone Clinic의 설명](https://www.stoneclinic.com/video/Shoulder-Wall-Pushup)과 기존 가이드를 참조했으며 그 영상·이미지는 사용하지 않았다.

**한계:** 측면의 단순 동작 도해다. 손 간격, 팔꿈치의 옆 방향 벌림, 견갑 움직임, 개인별 가동 범위·체형을 재현하지 않는다. 전문가가 자세 정확성을 검증한 시범이라고 표시하지 않는다. 이 한계를 화면에도 명시한다. 전체 운동의 전문 시범 라이브러리 요구는 아직 완료가 아니다. 더 넓은 동작 지원에는 운동별 접촉/관절 기준, 시작·끝 자세, 금기 상황 및 전문가 검토가 필요하다.

이 검사는 실제 React 컴포넌트를 임시 로컬 HTTP 서버와 독립 Edge 프로필로 실행한다. 기본 모드는 OCR 파서를 지연 Promise로 대체하며 합성 값·계정 표식·저장 오류를 주입한다. 저장 API는 실제 localStorage이고 계정 표식의 탭 간 storage 이벤트는 실제 브라우저 이벤트다. 로그인/Supabase 계정 전환은 모사이며 전체 인증된 Next 화면을 통과한 검사가 아니다. 운동 설정 영속성에는 테스트 호스트의 fixture-settings 키를 사용한다. 도해 시간 제어는 Playwright clock으로 실제 requestAnimationFrame 콜백을 진행시킨다.

**외부 요청 전송 0건**은 이 로컬 검사 환경의 범위다. 테스트 라우터가 OCR의 공개 worker/core/model URL을 로컬 설치 파일로 응답하고 다른 외부 요청을 차단했다. 운영 앱 전체의 네트워크 보장이나 새 오프라인 OCR 배포를 의미하지 않는다. 기존 운영 OCR의 공개 CDN 모델 다운로드 동작은 변경하지 않았으며 새 건강정보 전송 코드를 추가하지 않았다.
