# 기존 한국어 + 후보 일본어 캐릭터 검토본

사용자 2026-10-02 23:04 KST 청취 의견: 기존 한국어와 후보 일본어가 가장 비슷하게 느껴지며, 언어에 따른 억양·음색 차이는 조금 있음. 23:09 KST 요청에 따라 이 조합의 캐릭터 미리보기를 준비했고, **23:30 KST 사용자가 “확인 완료 문제 없습니다.”로 검토를 완료했다. PHASE 12 표본 PoC 완료, 전체 기술 PoC 11/16.**

이번 확인은 제공한 일본어 표본의 캐릭터 립싱크·쉼 자연스러움에 대한 수락이다. 자동 정렬의 모든 음소 경계를 개별 검수했다거나 실제 iPhone/모든 일본어 문장을 검증했다는 의미는 아니다. 음성·타임라인·검사 결과는 그대로 보존했다. 자세한 확인 범위는 `user-review.json`에 기록했다. 아래 미확인 표현은 검토본 제작 당시의 기록이다.

## 연결한 파일

| 항목 | 한국어 | 일본어 |
| --- | --- | --- |
| 음성 | 기존 Chirp3-HD Zephyr MP3 | 사용자가 제공한 Gemini Zephyr 후보 WAV |
| 길이 | 5.376초 | 5.080초 |
| 입력 | 저장된 한국어 원본 | `docs/yeoni-voice-comparison/media/gemini-zephyr-ja-user.wav` |
| 정렬 | 기존 한국어 타임라인 유지 | 이 폴더의 새 `alignment/timeline.json` |

기존 음성·외형·렌더러·입 보간은 보존했다. `evidence/preservation.json`에서 17개 파일을 작업 시작 커밋과 바이트 대조했다. 추가 음성 생성·유료 전환·외부 전송은 0회다.

## 자동 정렬

- 기존과 같은 Julius 4.6 / 공식 segmentation-kit monophone 모델을 사용하되 후보 WAV에서 새로 측정한 42개 구간이다. 이전 일본어 MP3의 시간을 늘이거나 재사용하지 않았다.
- 분석용으로만 16kHz PCM을 만들고, 실제 재생에는 첨부한 24kHz WAV를 그대로 사용한다. 자르기·속도·피치·음색 변경 없음.
- 승인 문장에서 지정한 읽기 `こんにちわ sp きょーわ sp ゆっくりいっぽずつすすみましょー`에 맞춘 강제 정렬이다. 독립 ASR 전사나 사람이 확인한 음소 경계는 아니다.
- 첫 발화 후보 0.2525초, 쉼 0.9425–1.5225초 및 2.0225–2.4025초, 마지막 발화 종료 4.7225초. 이후 무음 및 파일 끝 5.080초까지 입을 닫는다.
- `silB/silE→sil`, `sp→pau`, `q→cl`, `o:→o` 표기 변환만 적용했다. 측정된 장모음 구간은 분할하지 않는다.
- **청취 확인 필요:** 3.0325–3.4525초의 긴 `cl` 구간. 「一歩」의 촉음 후보로 정렬됐지만 실제 멈춤/경계가 적절한지는 미확인이다. 편의를 위해 임의 수정하지 않았다. 일본어 /u/의 모양과 표본에 없는 /e/도 이번 표본으로 최종 승인하지 않는다.

## 최소 코드 보완

- 타임라인 파서는 일본어 v2에 한해 `gemini-3.8-flash-tts/Zephyr`라는 구분된 음성 식별자를 받는다. 기존 Chirp 식별자로 잘못 기록하지 않는다. 기존 한국어 계약과 알 수 없는 음성 거부는 유지한다.
- 정렬 가져오기 함수와 CLI에 선택적 음성 식별자를 추가했고, 미지정 시 기존 Chirp 동작을 유지한다. 해시/문장/길이/음소 검증은 그대로다.
- 별도 `candidate-browser.tsx`, `export-candidate.mjs`를 사용하므로 이전 일본어 검토본도 보존된다. 동일한 `SpeechLab`, 하나의 재생기와 공통 Controller, 기존 외형 전환을 재사용한다.
- 음성 식별자는 입력 메타데이터다. WAV만으로 실제 생성 모델을 인증하는 기능을 뜻하지 않는다.

## 검증 결과

- 관련 한국어/일본어 타임라인·Controller·입 보간 코드 검사 **34개 통과**. 새 Gemini 식별자 수용, 기존 한국어 계약 유지, 다른 음성 거부, 오디오 해시 불일치 차단 포함. 프로세스 격리 환경에서 파일 단위로만 표시된 초기 실행을 결과로 사용하지 않고, `--test-isolation=none`으로 실제 34개 세부 검사를 실행했다.
- TypeScript 검사 통과, 변경한 TS/TSX 린트 통과. 전체 앱 빌드·관계없는 기능/이전 61개 외형 검사는 반복하지 않았다.
- Chromium 153 실제 브라우저 **7개 흐름 통과**: 후보 정확한 WAV/문장/자동재생 방지, 고양이·인간형 끝까지 재생/현재 음소·입 보간 프레임 일치, 발화 중 외형 전환, 원본 한국어↔후보 일본어 전환 시 정지/초기화, 일시정지·탐색·배속·화면 나가기, 이전 일본어 타임라인 오결합 거부/복구, 새로고침/320·390·1280px/오프라인 동작.
- 검사 중 렌더 시각과 미디어 시각 차이 최대 약 49.8ms. 이는 화면 갱신 시계 검사이며 음소 경계의 음향 정확도나 스피커/Bluetooth 출력 지연을 보증하지 않는다.
- 페이지 오류 0, 외부 요청 0. 발화 중 모양별 캡처와 두 외형 접촉 시트에서 눈·입 파츠 이탈/목 틈/명확한 겹침 없음 확인. 기존 외형 자산 및 렌더러를 바꾸지 않았다.
- 최초 검사 코드의 Blob fetch는 CSP `connect-src none`에 차단됐다. CSP를 완화하지 않고 테스트 관찰만 Blob 바이트 직접 해시 방식으로 바꿔 완료했다.
- WebKit/실제 iPhone은 이번에 검증하지 않았다. 이전 환경의 WebKit 공유 라이브러리 제약을 해결했다고 주장하지 않는다. 음색 선호 의견을 일본어 입 움직임 승인으로 확대하지 않는다.

## 재현과 다음 확인

1. `alignment/provenance.json`의 Julius/kit/model을 사용한다. 16kHz 분석 WAV와 같은 이름의 읽기 `.txt`를 별도 작업 디렉터리에 두고 kit에서 `perl segment_julius.pl <작업 디렉터리>`를 실행한다.
2. 원본 라벨을 보존하고 위 표기만 바꿔 `openjtalk-labels.lab`을 만든다.
3. `node --experimental-strip-types scripts/yeoni-japanese/prepare-timeline.mjs <원본 후보 WAV> docs/yeoni-phase12/media/approved-ja.txt <라벨> seconds <새 출력 JSON> gemini-3.8-flash-tts/Zephyr`를 실행한다. 기존 출력은 덮어쓰지 않는다.
4. `node scripts/yeoni-japanese/export-candidate.mjs /absolute/path/Yeoni_Korean_Japanese_Character_Preview.html`
5. `YEONI_CHROMIUM=<실행파일> node scripts/yeoni-japanese/check-candidate.mjs <위 HTML>`

사용자는 HTML에서 후보 일본어와 두 외형을 확인한 뒤 문제없다고 회신했다. 기술 검사와 표본 청취 검토를 합쳐 PHASE 12 PoC를 완료로 기록한다. 다음 PHASE 13은 실제 AI 응답과 발화 계획·감정·몸짓을 공통 Controller에 연결하는 단계다. PHASE 5의 별도 음소 경계/표본 밖 발음 검토와 PHASE 14/15의 기기 검증은 남는다. 운영 음성 교체, push, Preview/운영 배포, 새 TTS는 이번 확인에 포함하지 않았다.
