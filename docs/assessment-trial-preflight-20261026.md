# J6 발음 평가 — 시험 범위의 로컬 사전 검사

## 확인한 실제 빈틈

서버는 지정 계정의 `こんにちは。`·5초 이내 시험만 허용하지만, 브라우저 클라이언트는 연결 준비 확인 뒤 다른 문장과 최대 30초 WAV를 앱 서버로 POST할 수 있었다. Azure 호출 전에 서버가 거절하더라도 허용 범위 밖 문장·음성은 이미 브라우저를 떠난 상태다.

변경 전 합성 재현에서 승인 범위 밖 문장과 6초 WAV가 **모의 HTTP POST 1회**를 발생시켰다. 실제 네트워크·녹음·제공자는 사용하지 않았다.

## 로컬 변경

- `assessment-trial.ts`: 기존 envelope/서버와 같은 `trim()` 및 원문 1,000자 제한 뒤 고정 문장만 허용한다. 다른 구두점·추가 문장을 대체 문장으로 받아들이지 않는다.
- WAV MIME/실제 크기와 44바이트 표준 RIFF 헤더를 확인한다. PCM16·모노·16kHz·일치하는 RIFF/data 길이와 양의 완전한 샘플만 허용한다. 정확히 5,000ms는 허용하고 한 샘플 초과인 5,000.0625ms부터 거절한다. 확장 RIFF 청크는 기존 서버처럼 지원하지 않는다.
- `AssessmentBrowserClient.assess()`가 직렬화·POST 전에 이를 실행한다. 사전 검사에서는 헤더 44바이트만 읽는다. 로컬 거절은 전송하지 않은 요청 ID를 소모하지 않으며, 한 번 전송한 ID의 중복 차단은 그대로다.
- 기존 취소·30초 전체 대기 제한 안에서 검사한다. 읽기 중 취소/시간 초과 뒤 늦게 도착한 결과는 POST를 시작하지 못한다.

GET 연결 준비 확인은 변경하지 않았다. 이 GET에는 문장·음성이 포함되지 않는다. 실제 서버의 동일 시험 범위 검사·인증·동의·영구 한도·중복 차단도 변경하지 않았다. 브라우저 검사는 서버 방어를 대체하지 않는다.

## 검증 및 단계 경계

- 집중 Node 단위/계약: `node --experimental-strip-types --test app/language/practice/assessment*.test.ts lib/azure-pronunciation-server.test.ts` — **56/56 통과**. 클라이언트→서버 처리기 연결 검사는 모의 인증·원장·제공자를 사용한다.
- 변경 TS 4개 파일 ESLint 통과. `git diff --check` 통과.
- 전체 `tsc --noEmit --incremental false` 최종 통과. 최초 검사에서 신규 테스트의 넓은 `Uint8Array` 반환 타입 때문에 BlobPart 타입 오류 6개가 발생했고, 실제 새 ArrayBuffer 할당과 일치하는 `Uint8Array<ArrayBuffer>` 반환 타입으로 고쳤다. 타입 단언으로 오류를 숨기지 않았다.
- 정확히 5초/한 샘플 초과, 13개 잘못된 헤더 필드, 잘못된 문장·형식, 읽기 전 거절, 취소·타임아웃, 유효 요청의 두 점수 수신, 이미 전송한 ID 재사용 거절을 확인했다.
- 실제 브라우저 검사는 **미실행**. 기존 통합 검사기가 요구하는 `scripts/browser-qa/node_modules/esbuild/lib/main.js`와 `/opt/microsoft/msedge/msedge`가 이 클라우드 작업공간에 없다. Node 계약 검사를 실제 화면 검증으로 보고하지 않는다.
- 실제 로그인/DB/API, 마이크, Azure 평가, 발음 정확도·품질, 비용/보관 동작은 **미검증**이다. 서비스 활성화·비밀정보 읽기/변경·사용자 PC·push·배포는 하지 않았다.

이는 비활성 시험 기능의 전송 전 범위 검사 보완이며 **전문 발음 평가 J6 전체 완료가 아니다**. 로컬 자기 녹음의 기존 30초 제한은 바꾸지 않았다. 고정 문장·5초·1회 시험과 기존 OFF 상태를 확장하거나 해제하지 않았다.
