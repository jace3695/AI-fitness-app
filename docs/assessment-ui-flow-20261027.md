# J6 발음 시험 — 준비·취소·결과 화면 구분

## 확인한 실제 문제

- 기존 `AssessmentAvailability`는 일반 녹음 변환(최대 30초) 후 바로 동의/연결 준비를 열었다. 이미 추가된 클라이언트 시험 검사는 전송 버튼 이후 실행되므로, 다른 문장·5초 초과 녹음의 **로컬 거절**도 전송 후 결과 미확인처럼 안내했다.
- 요청 취소는 상태를 모두 비우면서 안내도 지웠다. 이미 보냈을 수 있는 요청의 처리·한도 상태가 불확실하다는 설명이 취소 뒤 남지 않았다.
- 성공 뒤에도 제목은 준비 중으로 돌아가고, 연결/내용 확인을 다시 누르면 결과나 성공 안내를 덮어쓸 수 있었다.

## 변경 범위

- UI 준비 단계에서도 기존 `ASSESSMENT_TRIAL`/`validateAssessmentTrial`을 재사용한다. 고정 문장과 5초 기준을 별도 정책으로 만들지 않았다. 다른 문장은 디코딩 전, 길이/형식은 WAV 준비 후 로컬에서 거절한다. 원본 녹음을 지우거나 로컬 다시 듣기·기존 30초 녹음 범위를 바꾸지 않는다.
- 성공한 로컬 준비에서만 안내·동의·연결 확인을 표시한다. 연결 준비 확인은 동의를 다시 해제하며, 사용자가 새로 동의하고 버튼을 눌러야 기존 평가 경로로 진행한다.
- 준비 취소는 음성 미전송을 안내한다. 평가 요청 대기 취소/백그라운드 전환은 결과 기다리기 중단일 뿐이며, 이미 전달된 녹음의 처리 종료나 1회 시험 한도 복구를 보장하지 않는다고 명시한다. 숨김 뒤 `pagehide`가 연이어 와도 이 안내를 지우지 않는다.
- 성공 제목을 결과로 표시하고, 내용 확인/연결 확인은 성공 결과를 덮어쓰지 못한다. 미완성/잘못된 응답은 기존 실제 결과 검증을 거쳐 점수 없이 실패한다.
- 녹음·문장·계정·요청 transport 변경, 세션 이벤트, 학습 계정 storage 변경, unmount에서 준비/동의/점수와 늦은 응답을 차단한다.
- 기존 브라우저 QA fixture의 정상 문장만 고정 시험 문장으로 맞췄다. 다른 문장 거절 부정 케이스는 유지·명시했다. 이 수정은 브라우저 실행 증거가 아니다.

- `node --experimental-strip-types --test app/language/practice/assessment*.test.ts lib/azure-pronunciation-server.test.ts tests/recorder-pitch-boundary.test.ts`: **66/66 통과**.
- 새 6개 테스트는 실제 컴포넌트의 handler/JSX와 실제 WAV 변환·시험 검사·브라우저 클라이언트를 연결한다. React 스케줄러, native 디코더, HTTP는 모의다. 단순 helper 테스트가 아니지만 실제 브라우저 검증도 아니다.

## 남은 검증과 유지한 경계

실제 브라우저 검증은 **미실행**이다. 이 작업공간에 기존 harness가 요구하는 `scripts/browser-qa/node_modules/esbuild/lib/main.js`와 `/opt/microsoft/msedge/msedge`가 없다. 렌더된 화면·작은 화면·실제 마이크·계정 로그인·실서버/Azure/DB·사용자 발음 품질과 비용/보관 동작을 검증했다고 보지 않는다.

기존 OFF, 지정 계정·`こんにちは。`·5초·1회 제한, 인증/서버 정책/한도/중복 방어는 변경하지 않았다. 실제 네트워크 평가, Azure/TTS 호출, 오디오 산출물 생성, DB 조작, 비밀정보 읽기/변경, 사용자 PC, push/배포를 하지 않았다. 운동 설정·신체 기록은 건드리지 않았다. **J6 전체 완료나 운영 준비 완료가 아니다.**
