# 결제 예정일·구독 점검 보강

2026-09-14 통합 실행 순서 **5번의 후속 범위**다. 추가 유료 API·요금제·서버 없이 기존 앱과 DB로 계산한다. Zephyr의 무료 조건 확인·재연결, ChatGPT 분석방 연결은 별도 대기 항목이다.

## 사용 순서

1. 가계부 **홈 → 결제 예정일 관리** 또는 **분석 → 결제 예정일과 구독 관리**를 연다.
2. **결제 예정일 추가**에서 상세 내역과 같은 장소 이름, 월 예정 금액, 매월 결제일, 시작 월을 입력한다.
3. 구독이면 **구독 서비스**를 선택한다. 마지막 사용일은 실제로 기억하는 날짜가 있을 때만 입력한다. 비워 두면 사용 여부를 판단하지 않는다.
4. **예정일 저장 전 확인**에서 변경 전후를 읽고 **설정 저장**한다. **취소**하면 저장하지 않는다.
5. **저장한 예정일**을 펼쳐 수정·안내 중지·삭제할 수 있다. 삭제와 안내 중지는 실제 구독 해지가 아니며 지출 내역을 바꾸지 않는다.

Jace가 직접 입력해야 하는 값은 실제 결제일·금액·구독 마지막 사용일이다. 이 값은 결제 기록만으로 확정할 수 없어 자동 입력하거나 개인 기록을 대신 작성하지 않았다. 기능 개발을 기다리게 하는 사전 작업은 아니다.

## 안내와 계산 기준

- 매월 1회 일정, 장소별 최대 한 설정, 계정당 최대 100개. 29~31일이 없는 달은 말일로 표시한다. 장소의 숫자·지점·부분 문자열을 합치지 않고 공백·대소문자만 정규화한다.
- 홈은 선택한 조회 월과 별개로 **오늘이 속한 달**의 예정일을 점검한다. 오늘까지 같은 이름의 기록이 없고 예정일이 3일 이내이거나 지난 항목을 표시한다. 기록 미확인은 미납 확정이 아니다.
- 앱을 열었을 때의 안내다. 앱을 닫아 둔 상태의 예약 푸시·OS 알림 권한·새 cron·외부 서버는 이번 범위에 없다. 날짜는 기기의 달력 날짜로 계산하고 자정 경과·화면 복귀 때 갱신한다. 다른 기기에서 추가된 기록은 **예정일·기록 다시 불러오기**로 확인한다.
- 구독의 실제 마지막 사용일을 입력한 경우에만 경과 일수를 계산한다. 30일 이상이면 다음 결제 전 계속 이용할지 점검하도록 안내한다. 입력 누락을 미사용으로 바꾸거나 결제 기록으로 실제 사용 여부를 추정하지 않는다.
- 같은 이름의 이 달 기록 건수·합계를 표시한다. 미래 날짜는 오늘 납부로 표시하지 않는다. 충전카드 충전은 지출 합계와 일치 검사에서 제외한다. 예정액과 기록 금액의 차이는 요금 변경 **확인 대상**이다.
- 이번 달 하루 예산 참고치는 `예정액 − 같은 이름의 이 달 기록 합계`의 양수 부분을 남긴다. 같은 장소의 지난달 추정액을 다시 더하지 않는다. 중지한 설정은 예상액에서도 제외하며 과거 달은 오늘의 설정으로 다시 계산하지 않는다. 실제 잔액·납부 상태나 자동 은행 조회를 뜻하지 않는다.
- 월별 지출 증가 설명은 같은 기간의 건수·건당 평균·사용처별 증감과 증가액이 큰 최대 두 사용처를 표시한다. 가격 인상·낭비·심리적 원인을 단정하지 않는다. 미래 지출과 지난달의 비교 기간 이후 기록은 설명에서 제외한다.
- 기존 반복지출 자동 감지 후보와 직접 입력한 예정일은 용도가 다르다. 자동 후보를 확정·해제하는 기존 경로가 직접 입력한 일정·사용일을 덮어쓰지 않는다. 새 상세 값은 기존 무료 AI 조언 요약에 자동 추가하지 않는다.

## 저장·DB·원본 보존

호스팅에 `20260914225836_budget_payment_plans` 마이그레이션을 적용했다. 사용자별 일정 테이블과 작은 재시도 확인 테이블을 추가했으며 기존 지출·수입·저축·반복 설정을 변환하는 SQL은 없다. 확인 테이블에는 요청 해시와 ID·결과만 저장하고 장소·사용일 전체 원문은 복제하지 않는다.

- 두 테이블의 소유자 RLS, 함수 `SECURITY INVOKER`, 빈 `search_path`, anon 실행 불가를 확인했다. 입력 계정과 실제 로그인 계정을 서버에서 다시 비교한다. [Supabase 함수](https://supabase.com/docs/guides/database/functions), [RLS](https://supabase.com/docs/guides/database/postgres/row-level-security).
- 원본 행 전체가 같을 때만 수정·삭제한다. 한 계정의 설정 변경을 직렬화해 두 창의 충돌과 개수 제한을 처리한다.
- 저장 요청은 계정별로 보관하고 같은 ID로 재시도한다. 응답 유실·재조회 실패 때 완료로 표시하지 않는다. 삭제한 설정의 과거 생성 요청을 다시 보내도 복구되지 않으며 이후 수정도 덮어쓰지 않는다.
- 확실한 입력 오류나 충돌이면 요청을 정리하고 서버 설정을 다시 읽는다. 처리 여부를 알 수 없는 실패이면 같은 요청 확인을 유지한다. 생성·수정·삭제 결과를 읽은 뒤에만 완료를 표시한다.
- 호스팅 적용 전후 지출 36건, 앱 상태 2행, 언어 상태 2행의 전체 행 해시가 일치했다. 수입·저축·반복 후보 설정은 각각 0건 유지, 새 일정·재시도 확인 행도 0건이다. 대표 개인 기록에 합성 값을 쓰지 않았다.
- 가계부의 지출·수입·저축 기록 초기화는 기존처럼 설정을 유지한다. 결제 예정일과 입력한 마지막 사용일도 설정에 속하며, 지우려면 예정일 관리에서 해당 설정을 삭제한다. 계정 삭제 시에는 소유자 외래키의 연쇄 삭제가 적용된다.
- 보안 진단의 새 경고는 없으며 기존 유출 비밀번호 보호 비활성 경고만 유지됐다.

## 검증 결과

- 코드 `a1985bf54894cc9c89e714bea5c815dc26ef82e8`의 [Actions 34906924438](https://github.com/jace3695/AI-fitness-app/actions/runs/34906924438), job `104185656512`가 전체 성공했다. 단위/DB 312개·VM 25개·lint·TypeScript·격리 프로덕션 빌드 통과, 실제 브라우저 **60/60** 통과다.

- 같은 SHA의 Vercel Preview `dpl_HZLp14o7ktuxG4T9WsiaCxpxnZz9`가 READY이며 Preview 대상(`target: null`)임을 확인했다. 이후 결과 정리 커밋은 문서만 바꾼다.
- 호스팅 테스트 계정의 핵심 저장 흐름은 닉네임 최초 설정 제한으로 미검증이며 재시도하거나 우회하지 않았다. 실제 iPhone 확인은 전체 무료 개선을 마친 마지막 단계에 진행한다.

## 사용자가 할 일

지금 개발을 계속하기 위한 추가 결제·API 키·환경변수 입력은 필요하지 않다. 이 기능을 사용할 때 위의 실제 결제일·금액·사용일만 직접 입력하면 된다.

Zephyr 음성의 대기를 해소하려면 기존 Google Cloud TTS 프로젝트의 결제 연결 상태와 무료 문자 한도에 합산되는 이번 달 전체 사용량을 확인해야 한다. 이전 Google Cloud 화면 접근이 막혀 앱 개발 쪽에서 확인하지 못했다. 새 결제 계정을 연결하거나 유료 호출을 켜지 않는다. API 키·결제 정보는 대화에 보내지 않는다.

실제 iPhone 홈 화면/PWA·저장·음성·화면 잠금 검사는 마지막에 진행하며, 아직 PR #189를 병합하거나 운영 배포를 하지 않는다. 닫힌 앱의 예약 푸시와 구독 실제 사용량 자동 연결은 이번 무료 구현의 완료 범위에 포함하지 않는다.

다음 무료 작업은 통합 순서 6번이다. 빠른 명령 화면과 `/api/assistant/chat`의 기존 처리 경로를 확인했다. 현재 지원하는 조회·할 일·운동·학습·루틴 명령을 바탕으로 공통 실행 전 확인, 요청별 중복 방지, 변경 전후 이력·되돌리기를 연결하는 검증이 필요하다. 이번 일정 관리 작업에서 이 명령 경로를 수정하거나 6번을 완료 처리하지 않았다.
