## Evidence delivery

Local commit, uncertain persistence, server pending, and independently acknowledged server delivery are distinct. Before any prepared event commit can execute, the adapter replaces any older server-verification label with an unavailable state that claims neither local persistence nor verification. Exact event/transition/current-graph readback changes only delivery status to pending before the separate batch write; it cannot adopt a new draft/handoff or trigger feedback early. Metadata-only transitions do not invalidate prior event delivery. Active-run restore/recovery performs a bounded readonly slot-specific pending-outbox scan; local absence never claims server verification. Each new local event freezes its exact predecessor batch; explicit delivery reuses persisted IDs/order/bytes and merges persisted batches with orphan events into one sequence-ordered plan. A successor is not dispatched unless each earlier step has independently acknowledged readback; incomplete readback leaves the outbox pending. An event commit followed by batch-write failure is distinguished from an uncertain event commit. A retained batch-persistence uncertainty is recovered with its exact candidate; after a crash loses that unpersisted candidate, the exact immutable event is recovered without rewriting its identity. A crash gap between event and batch can use immutable local predecessors, or a bounded authenticated prefix followed by exact local event/hash lookup. Missing or partial provenance stays blocked. Delivery cannot invoke a legacy mutation.

The UI offers explicit server confirmation while the local captured run is open; it does not promise background delivery after navigating away. A pending outbox is retained, never presented as a server receipt. There is no additional outbox, registry, background enrollment or retry service.

## Verification and limits

Source-loaded adapter/component/page tests use real repository, registries, language identities/coordinator, mutation runner/planner and (for privacy/delivery) the existing isolated SQL fixture. The UI test harness provides deterministic hooks, committed host refs, layout rectangles and frame callbacks. The existing source loader now passes its actual filename to TypeScript so `.ts` generics are not parsed as JSX; the other approved existing harness additions are isolated query-string setter/getter methods and a Suspense symbol and single-child root unwrap only for the exact actual ReviewPage mount. All other pages, including Learn, and all generic component overrides retain their original opaque shape. The latter executes the actual page source but does not model suspension, nested reconciliation, fallback scheduling or browser navigation. Closure tests add exactly the new adapter's named repository factory import and narrowly named business participants, while retaining constructor/registry/dynamic/test-loader prohibitions. No raw-storage authority exception or unrelated digest pin was expanded.

Full aggregate/type/lint/build acceptance belongs to the parent's final frozen-candidate run. Browser runtime, Chromium/WebKit, 320px keyboard/layout, true IME behavior, interrupted real IDB, real HTTP readback, owner/reset changes and disposable cleanup are unverified by this source slice. The separate runner-only enabled-copy builder, browser spec/workflow invocation and runtime acceptance are not implemented here. The local browser launch denial was not retried or escalated.
