# PHASE 9 — 인간형 기존 음성·립싱크 연결

2026-10-01 15:05 KST 사용자가 현재 상태를 확인한 뒤 다음 단계 진행을 요청했다. PHASE 8 원본 보존 인간형에 기존 `LipSyncPlayer`와 `CharacterController`를 연결한다. 원본 그림·승인 눈/입 패치·5.376초 MP3·60개 음소 자동 정렬은 변경하지 않는다. 새 TTS 요청은 없다.

`SpeechLab`은 고양이와 인간형의 재생·파일 검증·구간 듣기 화면을 공유한다. 인간형은 `speech` 스냅샷만 공통 Stage에 전달하며 자체 음소 매핑이나 타이머를 만들지 않는다. 재생 시간 갱신마다 렌더러를 다시 만들지 않으며, 일시정지·정지·끝·오류·버퍼 대기에는 같은 Controller가 닫힌 입으로 돌아간다.

[독립 미리보기](Yeoni_Human_Speech_Preview.html)는 원본과 승인 자산, 기존 MP3를 내장한다. 파일을 브라우저에서 열고 ‘저장된 연이 음성 불러오기’ → ‘재생’을 누른다. ‘조금 쉬는’·‘좋겠어요’ 구간을 정상/0.5배속으로 들을 수 있다. 작은 화면에서는 발화 그림을 크게 표시하고, 넓은 화면에는 원본을 나란히 표시한다. ChatGPT 내부 HTML 미리보기에서 실행이 차단되면 별도 영상으로 확인한다.

## 2026-10-01 중단 지점 복구·검증 결과

재구성된 `CHECKPOINT.md`/ZIP과 GitHub `8e09415c38bfbe9f7540c14c305f29ce90c2a89e`의 파일 해시 11개를 대조했다. ZIP에는 소실된 미커밋 패치가 없어서 기록된 요구사항에 따라 로딩 수정만 다시 구현했다. 소실된 패치와 바이트가 같은 복원본으로 주장하지 않는다.

WebKit은 MP3 교체 시 길이를 먼저 0초로 보고할 수 있다. 메타데이터 이벤트만 기다리는 첫 수정에서는, 이후 길이가 5.376초로 바뀌어도 추가 이벤트가 오지 않아 15초 제한에 걸리는 경우를 재현했다. 최종 수정은 `loading` 동안만 100ms마다 길이를 재확인한다. `loadedmetadata`/`durationchange`에서도 확인하고, 정상 길이를 얻으면 재확인을 끝낸다. 기존 15초 제한, 양수 길이의 100ms 초과 불일치 거부, 파일 교체·오류·해제 시 타이머 정리를 유지한다. 이미 재생 중인 상태는 후속 메타데이터 이벤트로 초기화하지 않는다.

## 로딩 수정 재검증 명령

```sh
YEONI_BROWSER=chromium node scripts/yeoni-speech-poc/check-loading.mjs
YEONI_BROWSER=webkit node scripts/yeoni-speech-poc/check-loading.mjs
```

프로젝트 루트에서 실행하며 Playwright 브라우저와 해당 런타임 의존성이 필요하다. 기본 설치 대신 준비한 실행 파일은 `YEONI_CHROMIUM` 또는 `YEONI_WEBKIT`으로 지정할 수 있다. 이 스크립트는 원본 비교·이미지·영상 생성 없이 이번 로딩 변경만 검사한다. 기존 `check.mjs`와 `check-visual.mjs`는 종전 광범위 검증 이력이며 이번 복구에서 재실행하지 않았다.

이번 업로드는 이미 수행한 로컬 최종 검증을 근거로 한다. 원본 비교와 영상 생성을 다시 자동 실행하는 기존 CI를 피하도록 커밋에 `[skip ci]`를 사용한다. 신규 GitHub Actions 실행 성공을 주장하지 않으며, PR #207은 Draft 상태로 유지한다.
