# 끼니별 식단 명령 검증 — 2026-09-16

## 지원 범위

- `오늘 점심 단백질 30g 기록해줘`, `오늘 저녁 단백질 27g 기록해줘`
- `오늘 점심 밥 130g 기록해줘`, `오늘 저녁 밥 80g 기록해줘`
- 오늘(한국 시간) 점심 또는 저녁의 식품 단백질 g·조리된 밥 무게 g를 **해당 끼니의 총량으로 교체**한다. 한 명령에는 수치 하나를 받는다. 단백질은 0~100g, 밥량은 0~1,000g 정수이며 0g도 명시적으로 기록할 수 있다.
- 음식의 무게에서 단백질을 추정하거나 공기·인분을 g으로 추정하지 않는다. 다른 날짜·추가량·여러 수치·불확실한 문장은 저장하지 않는다.
- 15분 확인 화면, 같은 탭에서 이동·새로고침 후 복구, 동일 요청 재확인, 기존 식단 실행 이력과 되돌리기를 사용한다. 기존 물·메모 명령과 과거 이력은 기존 형식을 유지한다.

## 원본 보호

- 단백질 변경은 끼니 상세, 하루 합계 저장소, 일별 요약 합계를 한 트랜잭션으로 갱신한다. 다른 끼니·아침/오후/저녁 보충제·점심 보충제의 기록된 값을 유지한다. 기존 합계와 상세가 불일치하면 수정 전에 식단 화면 확인을 요청한다.
- 밥량 변경은 해당 끼니의 밥 상세와 선택값을 갱신한다. 밥 종류가 기존에 있으면 보존하고, 없으면 `기타 / 종류 미기록`으로 둔다. `estimatedCarbs`는 기존 화면의 참고 계산(조리된 밥 g × 0.3의 반올림)을 유지하며 실제 탄수화물 측정값으로 취급하지 않는다.
- 기존 계산 정의에 따라 단백질 목표·점심 단백질 포함·저녁 밥량 요약 플래그를 해당 변경 범위에만 맞춘다. 식사 완료 여부, 마지막 식사 시각, 공복, 물, 메모, 일정, 다른 날짜와 알 수 없는 추가 필드는 보존한다.
- 끼니 값만 처음 저장해도 식단 화면에서 표시되도록 빈 필드를 중립적인 화면 기본값과 합친다. 저장하지 않은 `18:30`을 새 기록에 만들지 않는다. 외식 모드에서도 기록한 점심 식품 단백질 g를 볼 수 있다.
- 확인 당시의 관련 일별 저장소·초기화 표식을 DB에서 다시 비교한다. 이후 수정이 있으면 저장·되돌리기를 거절한다. 없는 키/날짜, 기존 JSON 문자열 저장 형식, 다른 날짜를 보호한다.
- 기존 `assistant_diet_command_history`와 소유자 RLS, 초기화 잠금, Auth 삭제 외래 키를 재사용한다. 새 함수는 `security invoker`, 빈 `search_path`, 인증 사용자 실행 권한으로 제한한다.
