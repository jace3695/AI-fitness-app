## 확인한 미구현 범위와 이번 연결

기존 `fitnessAiSnapshot.ts`는 body/weightManagement 집계를 생성하지만
`freeFitnessReport.ts`와 `localWorkoutPlanProposal.ts`의 무료 결과는 체성분 출처·추세를
판단 근거로 사용하지 않았다. `bodyMetricComparison.ts`는 기록 화면에서 이미
같은 출처의 추세를 표시하나, 무료 코치의 측정 신선도와 계획 검토 안내로 연결되지 않았다.
`oa-complete-report-local-review.md`, `oa-ocr-recovery-review.md`, OA 원문 항목 목록과
저장·날짜 병합 코드도 대조했다.

`FitnessAiCoachPanel` 안에 **체성분·운동 무료 점검**을 추가하고 기존 6종 분석 버튼에서도
이 점검을 함께 실행하도록 연결했다. 독립 점검 버튼은 서버 요청 없이 동작한다.
6종 버튼은 기존 분석 요청을 유지하지만 새 결합 결과를 요청 본문이나 클라우드 이력에 추가하지 않는다.
`bodyWorkoutReview.ts`는 기존 `buildAdaptiveWorkoutReview`와 `buildWorkoutProgramContext`를
재사용해 현재 운동 타입별 주간 구성, 유지·증가·감소·교체·보류 근거, 변경 전후와 준비 조건을
체성분 비교 근거와 같은 화면에 보여준다. 기존 규칙은 수행·통증·피로·컨디션으로 판단한다.
체성분 수치로 운동 종류·중량·횟수를 새로 결정하거나 설정을 자동 적용하지 않는다.

### 원래 목표와 실제 연결 수준

| 목표 | 이전 코드/최소 점검 | 이번 완료 범위 | 남은 범위 |
|---|---|---|---|
| 지표 표시 | snapshot 집계 및 기록 화면 비교 | 출처·날짜 검증 후 8항목 상태 표시 | OA 외 양식 전체 지원 아님 |
| 지표 추세 설명 | 기록 화면 같은 출처 비교 | 기간·단위·기기 경계, kg/% 방향 차이, 누락·오래됨 구분 | 체중계 추정치를 근손실·운동 효과로 진단하지 않음 |
| 운동 타입/구성 추천 근거 | 기존 적응 제안 엔진은 수행/안전 기록 사용, 최소 점검과 분리 | 같은 화면에 기존 엔진의 구체 제안·현재 구성·체성분 참고 근거 연결 | 체성분 수치에서 특정 동작·강도를 결정하는 검증된 매핑 없음 |
| AI 연이 분석 연결 | 독립 무료 점검 버튼만 연결 | 직후·주간·월간·장기·계획 점검·계획안 6종 실행 시 함께 갱신 | 서버 분석 문장/이력 재작성 및 일반 채팅 AI 연결 미구현 |

체지방·BMI·몸통 지표를 보여주거나 변화량을 설명하는 것과, 그 수치를 운동 변경의
인과적 근거로 사용하는 것을 구분했다. 이번 결합은 **기록 기반 제안 + 체성분 참고 근거**다.
원래 요청의 모든 의미를 충족한 “체성분 처방 엔진”으로 보고하지 않는다.
기존 저장·무료 정책 안에서 연결했으므로 새로운 DB/서비스/유료 호출은 필요하지 않았다.

새 규칙:

- 체지방률, 지방량, 전체 근육량 추정치, 근육률, 골격근량(기존 값 참고),
  몸통 근육량·지방량 추정치, BMI의 8항목만 읽는다.
- 지원되는 OA 라벨·기기·원문 단위·매핑·입력 방식과 날짜를 검사한다.
  OA에 없는 골격근량 매핑을 만들지 않는다. PRO 미확인 몸통 값은 비교하지 않는다.
- 값은 재계산·환산·보충하지 않는다. 기존 OCR 전사 범위 밖의 값은 확인 대상으로 제외한다.
  기존 저장 형식에는 누락 BMI가 모호한 OCR 때문인지 단순 미입력인지 남지 않는다.
  따라서 그 원인을 추정하지 않으며, BMI 원문 확인 안내와 빈칸을 유지한다.
- 최근은 기준일로부터 30일 이내라는 **앱 표시 기준**이다. 임상 기준이 아니다.
  누락, 잘못된 값, 출처 미확인, 오래된 값, 최신 측정일에 없는 과거 값,
  최근 1회와 비교 가능한 복수 기록을 구분한다.
- 같은 항목·기기·라벨·단위·매핑의 연속 최대 12회 첫 값과 끝 값만 비교한다.
  중간에 단위/출처/값/원문 날짜 충돌이 있으면 연결을 끊는다.
  미래·존재하지 않는 날짜는 제외한다. 저장 날짜의 명시적 수정은 존중한다.
- 통증·신경 증상·허리 악화·높은 피로·중단을 먼저 확인한다.
  kg·% 방향 차이나 근육량 추정치 감소는 측정 조건과 수행 기록 확인으로 연결한다.
  근손실·운동 효과·허리 질환 적합성을 확정하지 않고, 보상성 운동량 증가를 제안하지 않는다.
- 기록 변경 시 결과를 지우고, 계정 세션 변경 시 이전 결과를 숨기고 다시 화면을 열도록 한다.

출처 메타데이터 일치는 수치의 의학적 정확성이나 실제 원문 검수 완료를 뜻하지 않는다.
OCR 원문 확인 필요 표시는 남겼다. 측정 조건은 저장되어 있지 않아 같다고 추정하지 않는다.
외부 AI·새 서버 요청·DB 스키마·실제 기록을 변경하는 코드를 추가하지 않았다.
기존 27종 시연과 미완료 3종 차단 코드는 변경하지 않았다.

## 후속 연결 검증 및 분리 범위

후속 변경 파일은 `bodyWorkoutReview.ts`, 해당 단위 검사,
`BodyCompositionCoach.tsx`, `FitnessAiCoachPanel.tsx` 및 합성 브라우저 검사다.
기존 18개 체성분 검사와 새로운 10개 결합 검사가 모두 통과했다.
첫 결합 검사에서 제외 동작을 보류로 기대한 1개가 실패했으나, 실제 기존
`applyDayRoutineEdit`는 이미 힙브릿지를 걸러냈다. 구현을 약화하지 않고 검사를
“제외 동작이 결과에 없고 원본 설정은 보존됨”으로 바로잡았다.

새 UI 검사는 24항목 통과했다. 기존 17항목에 분석 버튼 6종 연결과
원래 요청 본문 필드 유지 검사를 추가했다. 합성 6회 안정 수행으로 기존 햄스트링 교체
규칙을 유발해 변경 전후·지지대 준비 조건·체성분 근거를 확인했다.
외부 요청 0, 브라우저 오류 0이며 저장소 문자열은 실행 전후 동일했다.
`combined-review-390.png`를 직접 확인했다. 이는 실제 컴포넌트의 격리 검사이며
호스팅·실제 계정·물리 기기 검증과 구분한다.

배포 후보는 이 문서의 체성분/결합 로직·컴포넌트와 해당 테스트만으로 분리할 수 있다.
이미 기준 HEAD에 포함된 날짜/OCR·목록·시범 작업 전체가 이번 새 변경인 것은 아니다.
기존 운동 시범 증거 폴더의 미추적 파일은 건드리지 않았다.
현재 기준 HEAD를 운영 main에 합쳐도 된다는 의미가 아니며, 부모가 실제 운영 기준과
선별 변경 및 의존성을 검토한 뒤 별도 배포 범위를 정해야 한다.
