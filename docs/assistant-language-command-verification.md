# 6단계 후속 — 일본어 학습 완료 확인·실행 이력

2026-09-16. 연이 대화·빠른 명령의 일본어 학습 완료를 즉시 저장에서 **확인 후 저장**으로 변경했다. Preview와 공유 DB에 적용했다. 6단계 전체 완료를 뜻하지 않으며 식단·운동 등 나머지 기록 명령은 후속이다.

## 사용 방법과 범위

1. [빠른 명령](https://ai-fitness-app-git-fix-app-wide-reliability-jace3695s-projects.vercel.app/assistant/quick) 또는 연이 대화에서 **오늘 단어 학습 완료했어**라고 입력한다.
2. 날짜(한국 시간), 학습 종류, 현재 완료한 학습과 추가할 완료를 확인하고 **확인하고 저장**을 누른다. 취소하면 학습 상태를 바꾸지 않는다.
3. 언어 홈의 **기존 자유 학습 바로가기**에 반영된다. 가나·단어·문장·문법·복습 중 한 가지의 오늘 완료만 지원하며 퀴즈 점수나 교육과정 수업 결과를 만들어 내지 않는다.
4. [연이 실행 이력 → 일본어](https://ai-fitness-app-git-fix-app-wide-reliability-jace3695s-projects.vercel.app/assistant/history?area=language)에서 변경 전후와 저장 시간을 확인하고 **이 변경 되돌리기 → 확인하고 되돌리기**로 복구한다. 이력은 20개씩 읽는다. 언어 앱의 모든 수동 학습 이력을 모은 화면은 아니다.

어제·미래 날짜, 여러 학습 종류, 부정·취소 표현이나 학습 종류가 없는 완료 명령은 저장 제안을 만들지 않고 안내한다. 이미 완료한 학습은 추가 저장하지 않는다. 명령 화면의 확인 요청은 15분 동안 유효하며 같은 탭의 이동·새로고침 후 원래 요청으로 복구한다. 한국 날짜가 바뀌면 미저장 요청을 거절한다. 로그아웃·탭 종료 후 복구는 보장하지 않는다.

## 저장 보호

- `apply_assistant_language_command`는 로그인 소유자, 날짜·만료, 초기화 표시, 원래 완료 기록을 검증하고 학습 상태와 실행 이력을 같은 DB 트랜잭션으로 저장한다. 같은 요청 번호는 같은 이력만 반환한다. 응답 유실 뒤 재확인이나 되돌린 요청의 재전송으로 다시 완료 처리하지 않는다.
- 기존 학습 상태 중 `dailyRoutineProgress`와 `dailyLearningHistory`만 비교·교체한다. 과거 날짜와 추가 메모를 보존하며 오답·저장 단어·설정·교육과정 기록은 건드리지 않는다. 오늘 완료 목록 두 곳이 다르면 합집합으로 기존 완료를 보존한다. 손상된 기록은 덮어쓰지 않는다.
- 저장 이후 두 기록 키 중 하나라도 바뀌면 되돌리기를 거절한다. 확인 대기 중 새 학습이 생겨도 오래된 내용으로 덮어쓰지 않는다. 다른 설정만 변경된 경우는 해당 설정을 보존하며 처리한다.
- `assistant_language_command_history`에는 본인만 접근하는 RLS를 적용했다. 함수는 모두 invoker와 고정 search_path를 사용하며 익명 실행은 차단한다. 앱 소유자가 편집할 수 있는 기록이며 위변조 방지 감사 로그로 설명하지 않는다.
- 학습 또는 연이 기록 초기화는 해당 명령 이력도 제거하고 초기화 전 대기 명령을 차단한다. 초기화 RPC의 기존 소유자 잠금과 같은 잠금을 사용한다. 계정 삭제는 `auth.users` 외래키의 기존 cascade로 이력을 제거한다.
- 공통 무료 모드, Zephyr 문자수 제한, 개발자 모드 없는 Work 방식과 별도 일일 분석방 예약은 그대로 유지한다. 이번 작업은 외부 AI/TTS 생성 호출 없이 수행했다. 운영 병합과 실제 iPhone 최종 검증은 마지막 단계다.

최초 코드 `e9bea0ba37ccb4c1fdb15f44c3eb24788597ee1a`의 [CI 35057106270](https://github.com/jace3695/AI-fitness-app/actions/runs/35057106270)에서 단위/DB·코드·빌드는 통과했지만 Auth 검사의 계정 정리가 실패했다. 새 초기화 트리거가 상태 행 DELETE에도 실행되어, 앱 테이블 권한이 없는 Auth 내부 역할로 이력을 삭제하려던 문제였다. 검증용 컨테이너·볼륨·키 제거는 성공했다. 이 실행은 계정별 정리 성공 또는 브라우저 통과로 집계하지 않는다.

후속 migration에서 트리거를 초기화 표시 UPDATE에만 연결했다. 계정 삭제는 기존 외래키 cascade가 담당하며 Auth 내부 역할에 앱 테이블 권한을 추가하지 않았다. 제한된 Auth 역할의 실제 DELETE를 단위 DB 검사에 추가했다. 수정 코드 `9368d5239ecb6441715a3f7da27338e84125c42a`의 [CI 35057604606](https://github.com/jace3695/AI-fitness-app/actions/runs/35057604606)가 성공했고 실제 Auth 계정 삭제까지 통과했다. 같은 코드의 Preview `dpl_C88QNxjkYPRAtXGCUcMsqduCiGQQ`도 READY이며 운영 target은 아니다. 이후 문서 갱신은 앱 코드와 DB를 바꾸지 않는다.

새 브라우저 시나리오는 각 엔진 3개다. 취소·대화/빠른 명령 이동·대기 새로고침 복구, 실제 DB 저장 후 응답 유실·같은 요청 재확인, 언어 홈 재조회·원본 되돌리기, 독립 두 세션의 충돌·후속 학습 보호, 부정/날짜/모호한 명령·계정 격리·만료·이력 조회 오류·320px 가로 넘침을 포함한다. 테스트 계정과 DB는 CI 내부의 합성 자료이며 실제 iPhone 검사로 확대하지 않는다.

DB 보안 점검에서 새 테이블·함수에 대한 지적은 없었다. 기존 Zephyr/연결 내부 테이블의 의도된 기본 차단과 기존 [유출 암호 보호 설정 경고](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection)는 이번 변경 대상이 아니다.
