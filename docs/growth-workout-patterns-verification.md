# 루틴 기록일과 운동 기록 비교 — 2026-09-17

7단계 개인화의 두 번째 범위다. 자기계발 → 주간 코칭에서 선택한 루틴의 어제까지 최근 28일 중, 실제 루틴 기록이 있는 날짜만 운동 실행 표시와 비교한다. 운동 부담의 인과관계나 쉬었다는 사실을 추정하지 않는다.

## 구현

- 기존 요일별 집계의 날짜 범위·중복 우선순위(완료 > 진행 > 중단)를 재사용한다. 오늘·미래·잘못된 날짜·다른 루틴은 제외한다.
- `운동 기록 있음`: 기존 boolean `true`, 본운동 완료/진행/중단 상태 또는 본운동·일반 유산소·묵주기도 유산소·운동 후 유산소·철봉 완료의 명시적 표시가 있는 날이다. 중단은 완료로 표현하지 않는다.
- `운동 기록 미확인`: 실행 표시를 찾지 못한 날이다. 실제로 쉬었거나 운동을 하지 않았다고 뜻하지 않는다. 계획·메모·시간 숫자만 있는 기록이나 폼롤러만 한 날은 운동 실행으로 추정하지 않는다.
- 두 묶음에 서로 다른 루틴 기록일이 각각 4일 이상 있을 때만 비교 문구를 제공한다. 기록일 중 완료 비율 차이가 25%p 이상이면 차이를 설명하고 일정/목표 검토를 안내한다. 운동량·강도·피로·운동 전후 순서나 원인을 추정하지 않으며 자동 변경도 없다.
- 같은 날짜의 운동 기록 여부와 루틴 상태를 근거 표로 펼쳐 볼 수 있다. 마지막 조회 기준이며 `기록 다시 불러오기`로 두 기록을 다시 조회한다.
- 기존 `useGrowthData`의 인증된 소유자별 `user_app_state` 조회 결과를 전달한다. 새 DB 테이블·마이그레이션·API·추가 조회 요청·AI/TTS 호출이 없다. 저장·계획 변경 함수는 바꾸지 않았다.
- 전체 운동 기록 형식 또는 대상 날짜의 실행 표시가 잘못된 경우 운동 비교만 차단한다. 요일별 집계는 유지한다. 연결 실패/1,000건 이상의 불완전한 루틴 조회는 기존 차단 기준을 유지한다.

## 첫 자동 검사에서 확인한 테스트 준비 오류

- Chromium의 첫 비교 검사는 화면 수치·제안·근거·새로고침까지 통과했지만 원본 대조에서 실패했다. 테스트가 정상 클라우드 객체 대신 JSON 문자열을 주입했고, 기존 전역 동기화가 이 값을 객체로 정규화했다. 앱 저장 코드는 바꾸지 않고 원래 날짜도 보존한 정상 객체를 테스트 자료로 사용한다. 원본 전체의 엄격한 동일성 비교는 유지한다.
- 두 번째 검사는 기본 루틴 생성이 끝나기 전에 조회해 0행 오류가 났다. 제목 표시 후 실제 동기화 중 안내가 사라질 때까지 기다린 다음 자료를 조회하도록 두 새 검사만 보완했다. 오류 무시·재시도·시간 제한 확대는 없다.
- 보완 후 TypeScript·해당 파일 lint 및 전체 재검증을 통과했다. 두 실패 원인과 첫 실행 결과는 위 최종 성공 결과와 구분해 보존한다.
