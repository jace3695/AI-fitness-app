# 유산소 종류·총시간 명령 검증 — 2026-09-17 (한국 시간)

## 범위

- `오늘 유산소 실내 걷기 총 20분 기록해줘`
- `오늘 유산소 고정식 자전거 총 30분 저장해주세요`
- 오늘(한국 시간)의 **유산소 종류와 총시간**을 확인 후 저장한다. 기존 값이 있으면 입력한 값으로 수정하며 시간을 더하지 않는다.
- 기존 운동 화면의 8가지 종류와 1~300분의 정수만 지원한다. `총`을 생략하거나 걷기 장소가 불분명한 명령, 질문·조건·부정·다른 날짜·복수 명령은 저장하지 않는다.
- 일반 운동 완료·일부 완료·중단·통증·실제 세트·유산소 메모·운동 전후 유산소·철봉·폼롤러·계획·다른 날짜는 보존한다.
- 확인 요청은 15분 동안 유효하고 같은 탭의 화면 이동·새로고침에 복구된다. 같은 요청으로 저장 결과를 다시 확인해 중복 저장을 막는다.
- 공통 **연이 실행 이력 → 운동**에서 종류·총시간의 변경 전후를 표시하고 되돌린다. 확인 이후 같은 날의 운동 기록이 바뀌면 오래된 저장·되돌리기를 거절한다. 이전 운동 완료 명령과 역순 복구가 가능하다.

## 구현과 DB 확장

- 기존 날짜별 `ai-fitness-workout-completed-days` 저장소와 `assistant_workout_command_history`를 재사용한다.
- `20260916232300_assistant_workout_cardio_commands.sql`은 이력에 `command_kind` 열을 추가한다. 기존 이력의 기본값은 `completion`, 새 유산소 이력은 `cardio`다.
- 읽기 전용 계산 함수와 저장 RPC를 추가한다. 기존 완료·되돌리기·초기화 함수를 교체하지 않는다.
- 새 함수는 `SECURITY INVOKER`, 빈 `search_path`, 인증 사용자만 실행 가능하게 하며 기존 소유자 RLS·초기화 잠금·행 잠금을 적용한다.
- 기존 문자열/객체 저장 형식을 유지한다. 레거시 `true/false` 날짜는 기존 완료 의미를 유지하는 객체로 확장하며 되돌리면 원래 불리언으로 복구한다.
- DB 적용 전에는 기존 운동 명령·실행 이력을 유지하고 유산소 명령은 ‘아직 준비 중’으로 안내한다. 확인 요청을 만들기 전에 새 읽기 전용 함수의 사용 가능 여부를 확인한다.
