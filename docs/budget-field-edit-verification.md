# 가계부 금액 검색·항목 수정 검증

2026-09-14 통합 실행 순서 5번의 후속 범위다. 앞선 분류·월별 점검에 금액 조건 검색과 지출의 다섯 항목 수정을 추가한다. 원본 PDF 마지막 제안의 5단계와 통합 실행 순서의 5번은 서로 다른 번호다.

## 구현

- 상세 내역에서 최소·최대 금액(경계 포함, 같은 값으로 정확한 금액 검색)을 적용한다. 지출 결제수단 필터도 추가했다. 금액 조건은 수입·지출·저축 모두에 적용하고 결제수단은 지출에만 적용한다. 잘못된 금액·뒤집힌 날짜 범위는 오류를 표시하고 결과와 CSV 내보내기를 막는다.
- 검색 조건을 바꾸면 숨겨진 지출 선택을 해제한다. 현재 필터 결과가 CSV에도 적용된다. 기존 CSV의 문자 그대로인 `\\r\\n`·`\\uFEFF`를 실제 개행·BOM으로 고쳤고, 따옴표·개행을 보존하며 수식으로 해석될 수 있는 문자열을 이스케이프한다.
- 지출 1~100건을 선택해 분류 또는 금액·날짜·결제수단·장소·메모 중 **한 항목을 같은 값으로** 변경한다. 금액은 각 지출에 적용한다. 날짜 변경은 월별 집계에 반영된다. 결제수단 변경은 충전·사용 등 거래 유형을 유지하고, 장소 변경은 기존 분류 기억을 자동 이전하지 않는다.
- 확인 대화상자에서 선택한 내역 각각의 변경 전후 값을 볼 수 있다. 확인 전에는 저장하지 않는다. 메모를 비우는 것과 기존 `null` 값은 구별하며 되돌리기에서 원래 값을 복원한다.
- 서버의 원본 행 전체를 확인하고 한 건이라도 바뀌거나 삭제됐으면 전체 변경과 이력을 취소한다. 같은 요청의 응답 유실·새로고침·재전송은 한 번의 변경으로 확인한다. 이미 되돌린 요청은 다시 적용하지 않는다.
- 기존 분류 이력에 수정 항목과 전후 스칼라 값만 추가한다. 전체 거래 원문을 새 서버 이력에 복제하지 않는다. 거래 삭제 시 상세 이력도 제거하며, 삭제된 거래나 이후 변경을 되돌리기로 덮어쓰지 않는다. 기존 분류·기억의 되돌리기도 그대로 검증한다.
- 입력은 저장 후 거래와 이력을 모두 재조회할 때까지 잠근다. 서버 응답 형태가 예상과 다르면 완료로 표시하거나 확인 중인 요청을 지우지 않는다.

## DB 및 비용

마이그레이션 `20260914131417_budget_expense_fields`를 호스팅 DB에 적용했다. 기존 이력 테이블에 열을 추가하고 항목 수정 함수 한 개 및 기존 되돌리기 함수를 확장했다. 기존 거래를 변환하는 데이터 마이그레이션은 없다. 소유자 RLS 3개를 유지하며 두 함수의 SECURITY INVOKER·anon 실행 불가를 확인했다. [Supabase 함수 안내](https://supabase.com/docs/guides/database/functions).

적용 전후 지출 36건·앱 상태 2행·언어 상태 2행의 전체 행 해시가 모두 동일했다. 수입·저축 각각 0건 유지. 보안 진단의 새 항목은 없고 기존 [유출 비밀번호 보호 설정 경고](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection)만 유지됐다.

추가 유료 API·요금제·서버를 사용하지 않는다. 음식 사진과 네 분야 무료 Gemini 조언 정책을 유지하고 Zephyr 재연결은 무료 조건 확인까지 대기한다. 대표 개인 기록을 이용한 쓰기 테스트는 하지 않는다.

## 검증 상태

- 단위/실제 격리 DB 304개, 동기화 VM 25개, lint·TypeScript 통과.
- 새 브라우저 시나리오: 금액·결제수단 필터→실제 CSV 다운로드→선택 초기화→금액 변경 취소/저장→새로고침→되돌리기; 날짜·결제수단·장소·빈 메모의 저장/재조회/원본 복원; 응답 유실 복구와 독립된 두 로그인 세션의 충돌·되돌리기 거절. Chromium/WebKit 및 320px 화면에 추가했다.
- 실제 격리 브라우저와 Preview 배포 확인은 진행 중이다. 통과 전에는 이번 후속 범위를 검증 완료로 표시하지 않는다.
- 호스팅 테스트 계정의 전체 저장 흐름은 이전 닉네임 최초 설정 제한으로 미검증이다. 격리 Auth·PostgREST·Postgres의 브라우저 검증과 구별한다. 실제 iPhone 검사는 마지막에 한다.
