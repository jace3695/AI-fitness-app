## 2026-09-20 첫 휴식 안내 및 복귀 후 재생 실패

- 사용자 사진에서 첫 ‘완전 휴식’ 안내 없음, 다음 동작 음성은 재생, 저장 없이 종료·다른 앱 전환·재진입 후 ‘안내 재생’도 실패함을 확인했다. 전체 음성 정상 판정으로 처리하지 않는다.
- 타이머 없는 첫 동작의 안내 호출을 추가했다. 인증 계정이 준비된 후 한 번만 안내하며, 이미 다른 동작으로 진행했다면 늦은 첫 안내로 덮어쓰지 않는다. 자동 재생 제한 시 기존 안내 재생 버튼을 제공한다.
- 무음 활성화의 늦은 실패가 새 MP3의 src를 지울 수 있는 경합을 확인하고, 아직 무음 소스인 경우에만 정리하도록 변경했다. 이 코드 경합을 실제 iPhone의 유일한 원인으로 확정하지 않는다.
- 백그라운드에서 재생을 멈추며, 복귀 후 버튼 터치에서 보관한 MP3로 미디어를 다시 로드할 수 있게 했다. 재생 복구는 TTS 생성 재요청 없이 받은 바이트를 사용한다. 늦은 재생 결과가 종료·음소거 후 안내를 바꾸지 않게 한다.
- Chromium/WebKit에서 지연된 무음 실패, 소스 유실, visibility 변경, 저장 없이 종료·페이지 재진입·캐시 재생을 재현하는 검사를 추가했다. visibility 모의 검사는 실제 iPhone 앱 전환과 구분한다. 검증 결과는 PR에 기록한다.

## 수정

- 운동 세트·휴식·다음 동작·완료 안내의 `speechSynthesis`를 제거하고 기존 인증/월 승인/문자수 제한을 적용하는 `/api/tts`의 **ko-KR-Chirp3-HD-Zephyr**로 연결했다. 기존 문구를 유지한다.
- 타이머 시작 터치로 같은 오디오 요소를 활성화하고 다음 전환 문구를 준비한다. 준비 여부와 관계없이 타이머는 바로 시작한다. 완료 이벤트에서 두 안내가 서로 끊던 호출도 하나로 정리했다.
- 짧은 운동 안내(200자 이하)는 계정/월/문구 해시로 탭의 sessionStorage에 보관한다. 재생·일시정지·새로고침은 받은 오디오를 재사용한다. 일반 비서 답변의 기존 메모리 전용 정책은 유지한다.
- 생성 전 요청 번호 보관, 응답 유실 시 재생성 금지, 저장 용량 초과 시 기존 시도 기록 유지, 기기 음성으로 대체하지 않는 정책을 유지한다. 새 탭/다른 기기까지 동일 음성을 공유하는 기능은 아니다.
- 음소거·이전 안내 대체·통증 화면·종료·계정 변경 시 늦은 응답이 재생되지 않게 한다. 자동 재생이 막히면 이미 받은 안내를 버튼으로 재생한다.
- 빠른 다음 동작 이동 직후 타이머를 시작해도 서버의 5초 요청 간격에 부딪히지 않게, 새 생성 요청만 5.5초 이상 간격으로 순서대로 처리한다. 대기 중에도 타이머는 즉시 시작하며 음소거·종료·계정 변경을 전송 직전에 재확인한다. 실패 요청을 자동 재시도하는 기능은 아니다.
- 타이머 버튼 터치 영역은 최소 44px. 일시정지 시 음성 준비/화면 잠금 요청을 반복하지 않는다.

## 추가 수정: 운동 완료 화면의 하단 메뉴 겹침

- 사용자 사진과 호스팅 브라우저에서 공통 메뉴(z-index 90)가 운동 창(50)보다 위에 표시되는 원인을 확인했다. 운동 창 조상에는 별도 stacking context가 없었다.
- 첫 검증에서 iPhone용 ‘홈 화면 추가’ 안내(110)가 저장 버튼을 가리는 경우도 검출했다. 운동 창을 120으로 올려 진행·휴식·통증·완료 화면 전체가 공통 메뉴와 설치 안내를 덮도록 했다. 안쪽 컨테이너에는 하단 safe-area 여백을 적용한다. 종료 시 기존 메뉴가 다시 드러난다.
- 별도 AI 조언 WebKit 검사의 페이지 진입 `load` 대기 시간 초과는 DOM 로딩 후 실제 서버 동기화 완료를 기다리도록 수정했다. 조언 응답·한도·동의 검사 조건은 그대로다.
- 320px·390px/높이 640px에서 진행 버튼 클릭, 저장 버튼의 9개 지점 hit-test, 실제 저장, 새로고침 후 기록 보존, 종료 후 전체 메뉴 열기를 Chromium/WebKit 회귀 검사에 추가했다. 기존 기록은 보존하고 격리 계정만 사용한다.
- 로컬 타입 검사·변경 파일 린트 통과. 새 CI/Preview 검증 결과는 PR #189에 기록한다. 실제 iPhone 결과와 혼동하지 않는다.
