# 개발자 모드 없는 Work 기록 점검

2026-09-15 사용자 요청으로 기본 진행 방향을 Work 기반으로 전환했다. 일반 채팅용 MCP/OAuth 연결은 보류한다. **예약 생성과 현재 Work에서의 실행은 확인했지만, 무인 예약 실행의 완료는 아직 확인하지 않았다.**

## 적용한 흐름

- 기존에 연결된 Supabase 관리 도구를 사용한다. 개발자 모드·새 API 키·추가 유료 추론 API·음성 호출을 요구하지 않는다.
- 대상은 기존 대표 네이버 계정이다. 계정 ID와 이메일을 함께 확인하고 다른 계정으로 자동 전환하지 않는다. 식별자는 비공개 예약 설정에만 넣었다.
- 일정·운동·식단·언어·가계부의 최근 7일 요약을 기존 `yeoni_connector.summary`로 읽는다. 당일은 진행 중인 기간이다. 원본 메모·사진·대화는 가져오지 않는다.
- 조언은 영역별 `public.chatgpt_advice`에 저장한다. 서로 다른 영역의 민감한 통계를 한 영역에 섞지 않는다. 원본 기록 변경이나 OAuth 세션 위조는 하지 않는다.
- 사용자·한국 날짜·영역으로 결정되는 일일 ID와 `ON CONFLICT DO NOTHING`으로 동일 날짜 재시도를 중복 저장하지 않는다. 저장 전 요약을 다시 대조하고 1시간 이내 스냅샷만 사용한다. 저장 후 본인 행을 재조회한다.
- 매일 한국 시간 아침 8시 전후의 예약을 등록했다. 첫 예정일은 2026-09-16이다. 예약 도구의 생성 성공·활성 상태를 확인했다. 실제 첫 예약 실행·알림 도착은 미확인이다.
- 예약은 연결 도구나 승인이 막히면 중단 사실을 알리도록 했다. 과거 대화로 현재 기록을 대신하거나 실패를 0으로 표시하지 않는다. 예약 실행이 현재 Work와 같은 도구를 사용할 수 있는지는 첫 실행으로 확인해야 한다.

## 권한의 실제 한계

현재 Supabase 연결은 `postgres` 관리 권한이다. 이 작업의 고정 계정·요약 조회·조언 INSERT 제한은 작업 지침과 실행 쿼리의 제한이며, 연결 자체를 읽기/조언 전용 DB 역할로 축소한 것은 아니다. 따라서 개발자 모드를 쓰지 않는다는 이유만으로 더 안전하다고 주장하지 않는다. 브라우저에서 일반 사용자의 조회는 기존 RLS를 따른다.

기존 OAuth 연결 관리 화면에서 연결을 해제해도 **이 Work 예약은 중단되지 않는다.** 중단은 ChatGPT의 예약 작업에서 **연이 기록 점검·조언**을 끄거나 삭제한다. 기존 Supabase 연결 해제도 이후 접근에 영향을 준다. 앱 기록 초기화는 예약 자체를 해제하지 않으며 이후 예약에서 새로운 기록 부족 안내가 생길 수 있다. 삭제한 조언의 동일 날짜 재생성 방지는 실행 지침 수준이며 별도 영구 삭제 표식을 추가하지 않았다.

## 확인 결과

- 대상 계정 일치와 다섯 영역 요약 조회 성공.
- 2026-09-15 첫 점검 조언 5건 저장 및 후속 재조회 성공. 최근 7일 집계가 비어 있어 행동·지출·통증이 없었다고 해석하지 않고 계정·기록·동기화 확인 안내를 저장했다.
- 동일 저장 쿼리 재실행의 신규 저장 행 0건. 기존 조언을 덮어쓰지 않았다.
- 대상 계정의 원본 6개 테이블을 전후 비교했다. 행이 있는 지출·앱 상태·언어 상태의 전체 행 해시/행 수가 일치했고, 나머지는 양쪽 모두 행이 없었다.
- 현재 브라우저는 별도 Gmail 계정이다. 해당 계정의 전체 DOM 재조회는 자동 승인 검토에서 네이버 계정 작업 범위 밖의 정보 조회로 차단되어 재시도하지 않았다. 네이버 계정의 실제 조언 화면 표시·새로고침은 미검증이다. DB 저장 확인을 화면 확인으로 대체하지 않는다.
- 새 앱 코드·DB 스키마·DB 권한을 변경하지 않았다. 선행 363개/74개 검사 수치를 이번 Work 흐름의 신규 검사 결과로 재사용하지 않는다. 운영 병합·배포는 하지 않았다.

## Preview 공개 예외

앞서 복원 시도는 자동 승인 검토에서 구체적인 접근 설정 변경 승인이 필요하다는 이유로 거절됐다. 이후 2026-09-15 사용자가 Preview 공개 예외 제거·Vercel 로그인 보호 복원을 명시적으로 승인했다. 해당 Preview 도메인의 예외를 제거했고 Vercel 설정에서 공개 예외 목록이 비었음을 확인했다. 비로그인 OAuth 메타데이터 요청은 302로 Vercel 로그인 페이지에 이동했다. **Vercel 로그인 보호 복원 완료.** 앱 코드·개인 기록·Supabase 권한·예약 설정은 이번 작업에서 변경하지 않았다.

## 확인 위치
